# 普通怪攻击引起的镜头晃动：诊断记录

日期：2026-11-06

状态：历史诊断，已确认一类可复现的镜头问题；诊断时未修改游戏运行代码或正式测试。用户随后确认修复方向，当前源码已完成[小怪镜头取景修复](../camera-mob-framing-20261106/README.md)及工程验收。用户不记得具体关卡，诊断证据不能确定实际遭遇的是哪一种怪，也不能把夹具中的位移幅度当成用户实玩的精确重放。

## 发现了什么

镜头除了跟随玩家，也会把附近符合条件的普通怪范围预警或持续危险加入取景。危险出现、消失或改变时，镜头会在跟随人物与容纳危险轮廓／安全点之间重新选择中心和缩放；多只怪连续出招时，这种切换可以表现为画面快速来回移动或伸缩。诊断中的镜头震动量始终为零，复现的是**取景平移和缩放**，不是 Boss 命中反馈造成的震屏。

对应代码在[战斗镜头](../../scripts/ui/chronicle/boss_camera.gd)：正伤害的区域预警和活动危险进入玩家附近的判定时，可被并入取景范围；预警加入了额外 100 世界单位的相关范围，随后完整轮廓被纳入画面。即使最终没有算出需要逃离的安全点，危险集合自身变化仍可能改变取景。

## 复现与对照

诊断共 29 个案例、每例 1200 帧，使用实际 `EnemySystem`、`EnemyGeometry` 和 `BossCamera`；动作预算和数量上限没有改动。以下是 1280×720 固定夹具的例子：

| 敌人／招式 | 结果 |
| --- | --- |
| E03 轭骨奔兽：直线冲刺 | 按 B13 的预算与上限放置 8 只，玩家静止时也出现平移和缩放；缩放从 1 降至约 0.734。 |
| E10 钩轮牵阵者：直线钩击 | 按 B13 的预算与上限放置 4 只，玩家静止时也出现明显缩放，最低约 0.508；后续减速地带会延长相关危险存在时间。 |
| E12 碑背石龟：环形脉冲 | B17 配置下放置 4 只，玩家静止、无需逃离时，预警集合变化仍使镜头来回移动；该例缩放保持 1。 |
| E02 骨弓伥／E05 纸灯蛛：弹道攻击 | 分别以 B13 配置放置 7 只，在玩家静止的负例中，攻击正常释放，但镜头位移为零、缩放为 1，也没有触发安全点重算。 |

这些是人为放置敌人的隔离诊断，不是用户那一局的真实敌群。E06 背瓮行脚的落点、E09 撼钟尸卫的扇形重击也可能参与取景；E01／E04 的近战小扇形在此夹具中影响较小。E07 的号令、E08 的治疗和 E11 的召唤本身为零伤害，会被过滤；其后可能出现的有伤害近战仍可进入。L02 普通弹幕按当前数据属于不触发区域预警的弹体；L05／L06 的正伤害回声落点则可能进入。完整分类见[招式审计](catalog-warning-audit.json)。

射箭场景的体感不能因此被否定：混有冲刺、钩击等敌人，或玩家为躲箭移动时，镜头仍会因其他危险或跟随人物而移动；现有负例只说明上述独立弹道攻击在该静止夹具中没有直接拉动镜头。

## 补充边界

预警剩余时间逐帧变化会使安全点缓存的整份危险数据比较失效，导致额外重算，搜索距离也随剩余时间变化；安全点偶尔换侧，但换侧并不一定改变镜头取景，不能把每次换侧都算作画面抖动。在这 29 个无 Boss 案例中，对比一次镜头更新与“正常更新后再作零时间更新”，中心、画面原点和缩放结果完全一致，因此这批结果不支持把问题归因于更新两次。

夹具没有模拟玩家攻击、受伤或增援，也没有原生渲染与实际 HUD 障碍轮廓；报告的屏幕位移由镜头变换计算。结果能确认上述机制可以发生，不代表所有怪群都会如此。完整证据见[诊断摘要](diagnosis.json)、[B13 屏幕分析](B13/screen-analysis.json)及[总体屏幕分析](screen-analysis.json)。

当时建议减少普通小怪攻击对全局取景的争用，同时保留 Boss 和关键危险的可读性；该诊断本身没有实施修复。后续用户确认的规则、实际实现及验收见[修复记录](../../docs/implementation/2026-11-06_普通小怪镜头取景修复.md)。
