# 整备拖卡与人物原位检视

用户要求直接拖卡上阵，去掉人物详情中「辅助 1／辅助 2／候补」的配置按钮；查看人物和属性成长应更清楚，并在原处检视，避免整页跳转。本轮实现与自动检查已完成，最终画面仍可由用户继续反馈。

此前小尺寸点击人物会直接打开独立人物页，属性详情则以长文本通知框显示；在编队时查看后需要重新返回，打断了卡库和队伍的上下文。本轮将人物检视改为整备内的覆盖层与页签，仍保留明确关闭和返回方式。

## 编队与人物查看

- 主角固定出战，至多两名辅助；从下方人物列表拖到辅助位可以上阵或替换，两辅助位之间可以换位或移到空位，将已上阵人物拖回列表则移出编队。空位写「拖入人物」。键盘以 Space 拾起、Tab 选择辅助位或卡库、Enter 放下、Esc 取消；实际战役事务仍由原服务处理。
- 只有实际获得、存活且符合当前战役条件的人物可以配置；人物入池不等于获得。阵亡或未获得时说明原因，未获得人物仍可查看能力预览。待选奖励时须先完成选卡，再调整编队；同位、取消、落空和非法来源不写档，保存失败整体回滚。一次有效更换只提交一次自动保存与变更通知，不改人物资源、奖励随机状态或存档 schema。
- 选中人物可在原处打开详情，保留当前整备、战前整备或地图等来源上下文；页签为「能力」「属性·成长」「人物」。按用户后续反馈，整备预览只在名字右侧保留一个「详情」入口，底部不再另设两个重复入口。能力描述区分前台、后台和持有；属性表分列当前、Lv.1 基础、累计成长、持有和行装，并显示已获人物的经验及下一项技能解锁。未拥有角色按真实入手等级预览，经验不虚构为零，也不计入持有加成；预览依照现有已持有人物和当前行装计算。
- 本次不改变人物、能力、获取、装备、经验或保存规则；当前人物数据和状态仍是显示的唯一依据。原位详情支持键盘查看长内容、关闭返回，详情打开时底层不会误响应点击。

## 验证与证据

正式战役服务的拖卡专项 headless **143 项**、真实 OpenGL **151 项**通过；后者多 8 项截图尺寸检查，同组不相加。真实输入有 17 组鼠标按下、移动和释放尝试，其中 12 次启动原生拖拽、5 次因非法来源拒绝；覆盖拖入、替换、交换、移出、取消和保存失败回滚。队伍摘要 **155 项**通过；战斗 UI 自动流程还覆盖拾卡后开战、清理拾卡状态及首次 Esc 暂停／恢复。见[拖卡验证清单](evidence/2026-10-29/party-drag/logs/verification-metadata.json)、[两人编队](evidence/2026-10-29/party-drag/01-two-members-1280.png)和[1280 空位](evidence/2026-10-29/party-drag/02-roster-1280.png)。

人物检视专项 headless 和真实 OpenGL 均为 **362 项通过**，同组不相加；人物档案 **121 项**、九人立绘 **525 项**回归通过。27 张三尺寸画面覆盖已获得存活、阵亡及未获得预览的三个页签，见[人物检查清单](evidence/2026-10-29/party-inspection/character/verification.json)、[能力页](evidence/2026-10-29/party-inspection/character/screens/alive-abilities-1280.png)和[成长页](evidence/2026-10-29/party-inspection/character/screens/alive-growth-1280.png)。这些是检视夹具，不代表完整战役游玩。

整合后的情境导航真实渲染 **239 项**通过，覆盖地图中的人物检视、窗口调整与焦点返回；见[日志](evidence/2026-10-29/party-inspection/validation/chronicle_context_navigation_smoke.log)和[路线内检视画面](evidence/2026-10-29/party-inspection/context/01b-route-character-1280.png)。用户要求合并入口后，另用真实鼠标在两个尺寸完成 **14 项**针对性检查，并重跑受影响的拖卡渲染与正式战役三尺寸布局检查；[单入口画面](evidence/2026-10-29/party-inspection/character/screens/preview-single-entry-1280.png)、[布局画面](evidence/2026-10-29/party-inspection/reflow/roster-1280.png)。旧演练 UI 检查使用测试适配器，不能当成当前战役通关验证；其写入失败与回滚为有标记的故障注入。

必需 Godot 启动通过；最终 12 份日志校验、96 张截图及源码／配置哈希见[验证汇总](evidence/2026-10-29/party-inspection/validation/verification.json)。Graphify 受保护更新的 CLI 退出 0，但 Godot 提取器不可用、缺少 202 个运行脚本，候选被拒绝，保留 STALE 旧图，见[日志](evidence/2026-10-29/party-inspection/validation/graphify-update.log)。截图和自动检查不等同于整章人工游玩与平衡验收。
