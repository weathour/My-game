# 填写主题

依据：[当前设计共识](../00_当前设计共识.md)。方法见[讨论与评审](../15_游戏设计全景分析与评审流程.md)。按实际问题增删以下部分，无需填满完整体系。

## 本次问题

玩家会遇到什么情况，需要决定什么。

## 已确定与未定

分别记录用户决定、当前提案和仍待讨论的边界。运行事实注明版本与证据，不和目标混写。

## 建议与取舍

用必要的例子说明结果、代价和受影响的状态。不要替玩家预设最优玩法。

## 实施与验证（需要时）

描述对应改动、验证范围与结果；没有实现就明确写未实现。同步受影响的长期文档，撤下被替代方案。
