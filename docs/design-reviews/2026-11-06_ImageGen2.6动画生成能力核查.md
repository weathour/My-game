# ImageGen 2.6 动画生成能力核查

日期：2026-11-06。本文核查官方文档、本地工具接口及一次内置工具探针；未另行调用图像 API 或 CLI，也未修改角色素材。

## 官方能力

OpenAI 于 2026-11-04 发布 [GPT-Image-2.6 Sunburst 与 Flare](https://developers.openai.com/api/docs/changelog)；两者支持图像生成、编辑、复杂度控制、SVG 和动画 GIF。官方将 [Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.6-sunburst) 定位于更细致的视觉工作，[Flare](https://developers.openai.com/api/docs/models/gpt-image-2.6-flare) 侧重快速迭代。

按照[官方图像生成指南](https://developers.openai.com/api/docs/guides/image-generation#generate-animated-gif-output)，生成和编辑接口都可请求 `output_format=gif`；编辑接口还可用静态参考图引导动作。当前指南列出的 GIF 参数为：

- `frame_count`：2—16 帧，默认 9 帧；`frame_duration_ms`：每帧 20—2000 毫秒，以 10 毫秒为单位取整，默认 200 毫秒。
- `size` 指每一帧完成后的尺寸，可为 `auto`，或宽高均为 16 的正整数倍；帧数、尺寸和生成数量共同受模型限制及请求像素预算约束。官方示例使用 9 帧、每帧 200 毫秒，形成 1.8 秒动作。
- GIF 输出不支持流式返回、局部预览、自定义压缩、`prompt_rewriter` 或遮罩；所选模型还需具备 GIF 预览访问权限。参见[生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate)及[编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)。

两种接口当前都列出 GIF 预览权限要求。首次核对可选 `n=1`、`size=auto`；帧时长按指南的 20—2000 毫秒请求，不把接口页对编码延迟的单独描述推断为更大的请求范围。

提示词可以要求循环，但不能据此保证循环接缝或人物身份稳定。官方也提醒跨次生成的角色一致性和精确构图仍有局限。透明背景的接口说明要求 PNG／WebP，不能据此推断 GIF 可直接输出游戏所需透明图层；需单独验证。[官方指南](https://developers.openai.com/api/docs/guides/image-generation#generate-animated-gif-output)、[透明背景参数](https://developers.openai.com/api/reference/resources/images/methods/generate)

## 当前本地工具能控制什么

当前会话的内置图像生成工具公开提示词、参考图和透明背景开关，没有显式的模型、输出格式、帧数或帧时长参数；其底层模型身份也未公开。本次以金币为对象、在提示词中明确要求 8 帧和每帧 100 毫秒的真 GIF，实际返回单帧 PNG（1448×1086），并非动画；原始文件未转换或合成，见[探针记录](../../design/imagegen26-gif-20261106/probe/result.json)。这只说明本次入口调用没有验证直出 GIF 可用，不能据此认定底层模型为 2.6，或否定其官方 API 的 GIF 能力。

本机已安装的 `image_gen.py` 默认模型是 `gpt-image-2`，可传模型参数，但输出格式校验只接受 PNG、JPEG／JPG、WebP，且没有帧数或帧时长选项；这份旧 CLI 尚未适配本次所需的 2.6 GIF 调用。本轮不修改已安装技能或工具。

## 对人物动作的意义

此前流程通常先生成带多个姿势的静态图，再根据实际透明区域选帧。后续新制或重制时，入口实际支持 GIF 则优先采用 **已确认人物母版 → 分别生成动作短 GIF → Aseprite 提帧和整理 → 导出项目现用 PNG 帧图 → 接入现有 `SpriteFrames` 与控制器**；只返回 PNG 时继续用静态姿态表。直接取得逐帧动作有望减少猜测静态图行列的工作，动作是否更连贯仍须实测。

试做时仍需检查脸与装备漂移、身体缩放、脚底滑动、武器越界、循环接缝、透明层、共同色板与二值 alpha，并确认攻击接触帧。动画流畅不代表战斗时序正确：继续由真实施放事件驱动；即时结算从接触帧呈现，手动技能优先普攻，失败不播成功动作，暂停时冻结。比例、锚点和导出要求沿用[角色战斗美术流程](../art/角色战斗美术制作流程.md)。

GIF 源帧时长是制作参考，不自动改变战斗预警、命中或收势时刻；不透明结果只能作动作参考或另取透明源。建议以已确认母版先核验入口与透明、锚点，再据结果制作。当前角色素材是已验收基线，这次规范更新不启动批量重制，也不改变现有运行格式或规则。完整步骤、生成请求模板和只读核查命令见[角色战斗美术流程](../art/角色战斗美术制作流程.md)。
