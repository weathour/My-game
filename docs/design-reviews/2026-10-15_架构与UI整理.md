## 问题与决定

| 已核实问题 | 处理与对象责任 |
| --- | --- |
| 技能等级、构筑 getter 每次扫描玩家属性列表，且读取时初始化缺失字典 | 改为直接读取已知状态并校验类型；缺失值返回默认。写入/读档保留初始化和规范化责任 |
| 技能栏内嵌五种绘制对象，动画无关帧和隐藏时仍有处理回调 | 将控件拆到 `scripts/ui/hud/widgets/`；控件拥有绘制与动画生命周期，技能栏保留布局、数据转发、悬停和交互 |
| 重建布局释放拖拽图像后，拖拽字典仍持有旧对象 | 重建前取消拖拽；隐藏 HUD 与底部技能栏切人时同样清理，避免失效引用、隐藏控件截取鼠标或误交换另一角色技能 |
| 多套“天赋”定义与运行逻辑混杂，文档误称全部可达 | 角色天赋和退役节点分别归入 `role_talent_catalog.gd` 与 `legacy_skill_talent_catalog.gd`；系统保留原 API 别名、ID 和兼容逻辑 |
| 设置按键列表超出内容区域，最后几项无法访问 | 全部内容页共用滚动区域，关闭按钮固定，焦点自动滚动到可见区域 |
| Tab/Enter/Space 被 GUI 消费，改键失败；分类无选中态 | 设置组件在输入阶段处理捕获；分类状态可见，Esc 先取消捕获，Tab 焦点限定在弹窗，关闭后归还焦点 |
| 弹窗在入树前设置标题会丢失，空标题仍占位 | 共用弹窗保存标题/提示值，初始化时应用并隐藏空字段 |
| 静音无文字、性能开关归入音频、菜单字体与焦点状态不一致 | 补标签，性能开关归显示页；复用阅读字体、透明焦点描边和禁用样式 |
| 切人、Boss 时间、法师名称与结算文字不一致 | 按运行规则校正文案，保持技能、设置与存档 ID |
| 配置检查要求编辑器省略的默认字段，导致整套检查提前终止 | 接受 Godot 4.6.2 的 resizable=true / aspect=keep 默认值；显式错误值仍失败 |
| README、路线图与当前成长/商店相互矛盾 | 当前状态统一从 docs/08 进入；修正 5/10 级天赋位、停用等级天赋、每份 5 骨与按最高解锁 N 限额的携带规则 |

## 结构落点

- `player_skill_level_system.gd`：技能等级和天赋位状态；`player_skill_level_effect_flow.gd`：已实现的等级数值与预览；`player_build_system.gd`：发牌及构筑应用。
- `scripts/player/data/`：角色天赋与退役天赋纯定义。`player_skill_talent_system.gd` 仍负责查询、规范化与兼容，不恢复停用入口。
- `combat_skill_bar.gd`：布局和交互协调。`skill_cooldown_icon.gd`、`buff_status_icon.gd`、`switch_portrait_display.gd`、`ultimate_energy_display.gd`、`team_role_status_row.gd`：各自显示对象。
- `survivors_modal.gd` / `survivors_ui_theme.gd`：共享外壳、字体和控件状态。`main_menu_settings_panel.gd`：设置页及其完整输入生命周期，主菜单不再转发按键事件。

现有 `main.gd` / `player.gd` 已有较完整的 flow 委托，保留协调和兼容入口。此次不按文件行数拆散状态，不引入 ECS、通用事件总线或新的存档模型。
