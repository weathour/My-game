# 游戏设计评审：主线场景与叙事呈现

> 2026-10-26整理：本页保留当时的实现、问题或素材来源证据，正文中的“当前”“已定”“后续”指记录时点；不作为新体系要求或当前任务队列。目标以[当前设计共识](../00_当前设计共识.md)为准，新设计尚未实施。


本记录按[项目评审方法](../15_游戏设计全景分析与评审流程.md)保留0—16节。`implemented`表示已接入正式主线入口；不表示正常速度游玩、玩家理解或情绪节奏已经验收。

## 0. 决策摘要

原准备页主要由任务说明、NPC按钮和状态文字构成，原29个对话节点也以系统说明为主。玩家能完成交付，却很少从画面与人物反应理解为什么要走这三段路。

采用“等一声回答”的夜间通讯营地：保留“恢复通讯”章名与全部三关业务，用场景、可回看的物件、独立旁白和角色短句串联断线、调查与回应。正式入口已接入；完成条件包括原流程无回归、大小窗口可读、物件查看只读、保存失败不发布结果。真实玩家理解和返营阅读节奏单列待验证。

## 1. 范围与约束

目标是首次进入主线、在三次战斗之间返营的玩家。范围限准备页、对话、记录及本章文案和原画。任务结构、战斗时间、角色技能、怪物规则、奖励与保存业务沿用当前实现。

保持3任务、6交谈对象、3物品、13段29节点和3条情报。任务、对话、节点、选择、命令、道具及凭据ID不变，内容版本仍为1。不增加配音、新音乐、可行走剧情地图、回忆关卡、时间旅行、好感或支线系统。验证目标为1280×720与960×540，含键盘和120%故事文字。

## 3. 玩家问题与成功标准

原界面让玩家连续阅读“任务已记下”“记录页保留”等机制说明，人物更像流程提示器。现有证据支持这是内容与布局问题，尚无观察式玩家测试。

期望玩家先看到仍亮着的通讯台，再从记录、样本和核心理解三次出击之间的因果；需要操作时能迅速找到当前交谈、出击或交付。成功信号是玩家能复述“去哪里、取什么、交给谁”，辨认查看与交付的区别，并说出前哨回应与前面物件的联系。若玩家只记得漂亮背景、找不到出击或把查看当成交付，则设计主张不成立。

## 4. 状态与机制清单

| 状态域 | 所有者及本轮读写 |
| --- | --- |
| 主线任务 | `story_progress.gd`写；准备页读状态决定目标、NPC、路线与场景旁白 |
| 剧情物品 | 既有首通和交付写；数量决定物件查看入口是否出现 |
| 情报 | 既有交付写；已整理物件定向读取对应记录页 |
| 对话检查点 | 既有open/advance写；Esc保留，重开续读 |
| 已见节点 | 既有对话业务写；历史仅展示其旁白与台词 |
| 战局与结果 | 既有attempt/settlement写；继续、放弃、异常恢复门禁沿用 |
| 三人队伍 | 现有队伍面板保存；下一局生效，继续局保持冻结阵容 |
| 设置 | 现有设置接口写；阅读带读120%文字与减动画 |
| 位置与场景 | JSON静态内容及`story_visuals.gd`；只影响构图和文字 |
| 输入与焦点 | 当前面板管理；关闭恢复打开前焦点，不生成剧情奖励 |

关键机制是“查看物件”：前置为物品已持有或关联任务已交付；点击调用`journal.open(profile, tab_name)`；成本为零，任务、物品、情报和凭据均不改变。接取及交付仍必须在原对话选择中明确确认。

## 5. 链、环、网络与生态

动作链：营地看到当前线索 → 与NPC确认 → 原关卡出击 → 首通带回材料 → 营地出现待交付物件 → 显式交付 → 保留情报、解锁下一任务 → 环境短句变化。物件可在交付前查看用途、交付后回看成果。

资源流仍为首通材料 → 故事档持有 → 明确交付消耗 → 任务与情报永久化。线索积累让已走路线逐渐可理解；恢复环由检查点、原尝试身份和保存失败保留状态提供。练习重访不产永久材料，不能形成刷取循环。

准备与记录依赖既有故事业务及设置；既有战斗向其提供结果。没有改变敌人生态、角色组合或构筑解法，也没有借环境叙事新增可写进度入口。

## 7. 系统全景影响

受影响的是主线准备布局、对话阅读、记录回看、原画构图和阅读舒适度。任务及存档接口未改，物件查看不引入新状态；菜单仍从原故事选档进入。

移动空间、三角色轮转、普攻/技能/大招、伤害治疗、构筑/天赋、祝福装备、敌人Boss、波次/N层、奖励骨头阮石、战斗HUD和成就均不改变。继续/失败/放弃与最近结算仍复用原流程；BGM与界面音效仍使用现有系统。新增一幅原创营地画面，来源和完整生成提示词见[场景证据说明](../../design/story-20261025/README.md)；独立导出、性能基准和发布准备度不在本次结论内。

## 8. 整局生命周期

故事按自身三关时间轴验收，不套用无尽20波的12分钟时间轴。

| 阶段 | 目标及保留行为 |
| --- | --- |
| 故事选档后进入 | 正式准备入口能看到通讯营地、当前线索、队伍与返回 |
| 接任务与出击前 | 短句先建立原因，明确选择后开放原出击入口；可先整备 |
| 前哨清剿与返营 | 保持180秒目标；首通记录出现，交付后路线指向裂隙 |
| 裂隙推进与返营 | 保持210秒目标；样本与杂音联系，交付后确认星核位置 |
| 星核讨伐与返营 | Boss仍在135秒出现，胜利规则沿用；确认消耗1枚核心后得到回应 |
| 失败、退出与恢复 | 原任务和永久线索保留，本关构筑按原流程清理或继续 |
| 通讯恢复后 | 保留物件、情报与已见谈话；已通关地点可练习重访 |

自动UI测试可触发关卡胜利事件，因此只证明流程接线；三场正常速度战斗与返营阅读节奏仍需人工完整体验。

## 9. 退化模式与边界

没有新最优构筑或货币循环，固定路线也不增加伪分支。主要边界是美术挤占操作、未发现物件提前剧透、只读入口误写进度、小窗口选项被裁切、保存失败被隐藏及版本升级误伤旧档。

对应控制是右栏滚动和底部路线、发现门禁、定向只读记录、阅读带滚动、原节点错误提示及保留内容版本1。减动画立即显字；不用颜色独自表达状态。不新增循环动效、闪烁、配音或音乐。长文本、本地化扩张和真实玩家长时间阅读仍需后续证据，不能用短句数量替代验收。

## 10. 综合发现

P1：任务操作能走通，但主线缺少可感知的地点和人物动机；根因是功能说明承担了叙事。以营地物件和原创短句补足，不扩展业务系统。

P1：呈现改版可能破坏接取/交付、焦点与恢复。现有稳定ID和读写分层提供最小兼容路径，结构、进度及阅读检查已通过。

P2：玩家能否顺着物件建立记忆、是否愿意停留阅读尚无玩家数据。保持待验证，不用“更感人”或“已提升留存”描述当前结果。

## 11. 方案比较

| 方向 | 收益 | 成本与结论 |
| --- | --- | --- |
| 保持功能页与原台词 | 业务风险最低 | 原问题保留，不采用 |
| 原流程上加入场景、物件回看、短句与阅读带 | 建立地点、原因与返营变化，不改存档业务 | 范围可核验，采用 |
| 可行走剧情地图、回忆关卡、分支与配音 | 可扩大探索和演出 | 当前需要不足以支撑新系统、资产与保存成本，不采用 |

## 12. 决定与设计合同

决定为`approved`，已接入为`implemented`。主线页面标题为“等一声回答”，数据章名保持“恢复通讯”。

- `dialogue.location`：必填非空字符串，显示当前位置标签。
- `dialogue.scene`：必填字符串，仅`radio / outpost / rift`；对应同一营地原画的全景或不同局部构图，不增加故事空间或状态。
- `node.narration`：可选非空字符串，最长40字符；当前29节点均提供。旁白与角色`text`分开显示，当前台词27—40字符。
- 新字段不参与任务、道具或保存判断。保留全部稳定ID、选择、连接、条件、指令和凭据，`content_version=1`不变；`story_state`严格比对内容版本，纯呈现改动不触发升级。
- 主线推进仍只由原业务写入口执行。物件取得后可查看，交付后标“已整理”并打开情报；通讯台只回看已见谈话。未解锁路线名称不显示，练习重访保持原门禁。
- 确认先补全台词，再推进；跳过停在选择处。消耗及延期选择明确；Esc保留检查点。保存失败保留节点、任务和物品，错误可见；关闭恢复焦点。
- 阅读带保留120%故事文字、减动画、Tab焦点和滚动。记录`open(profile, tab_name = "任务")`只打开页签，历史仅拼接已见节点的旁白和台词。

若阅读带阻断核心选择、物件查看产生业务写入或旧档无法恢复，先修复或撤回受影响呈现；不得通过清档、改任务ID或弱化保存校验解决。
