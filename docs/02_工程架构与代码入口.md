# 工程架构与代码入口

2026-10-27：本页区分已落地的新界面与保留的旧战斗代码，供定位和评估复用。新设计见[当前设计共识](00_当前设计共识.md)，待实施的边界见[真实战斗架构提案](design-reviews/2026-10-27_真实战斗架构与参考实现.md)；不能因这里仍列有旧成长模块，就把旧规则恢复为设计要求。

## 工程与目录

- Godot 4.6.2；根目录 `project.godot`；主场景 `res://scenes/chronicle/chronicle_shell.tscn`（新主线与六个真实战斗节点）；旧版入口 `scenes/main_menu.tscn`，旧战斗场景 `scenes/main.tscn`。
- `scripts/battle/`：新的本关会话、人物运行态、能力、目标查询、敌人、伤害与关卡导演。
- `scripts/campaign/`：正式主线、奖励和原子保存；`scripts/content/combat_catalog.gd`：当前可玩人物、能力与装备定义；`scripts/content/stage_catalog.gd`：关卡分阶段敌人组合、成组数量、上限、Boss攻击顺序及地图配置。
- `scripts/game/`：战斗装配、刷怪、奖励、HUD、地图、会话及存档流程。
- `scripts/player/`、`scripts/player/roles/`、`scripts/abilities/`：角色、能力、旧成长、数值和运行状态。
- `scripts/enemies/`、`scripts/enemy/`、`enemies/`：敌人逻辑与作者配置资源。
- `scripts/combat/`：共享战斗规则；`scripts/ui/`：界面与主题；`scripts/save/`：保存和恢复支持。
- `scenes/`、`effects/`、`assets/`：当前场景、特效与运行资源；`design/`：素材制作源档。
- `archive/legacy/`：只读历史目录，不是当前运行实现。

## 当前入口

新界面代码在 `scripts/ui/chronicle/`：`chronicle_shell.gd` 协调页面，`chronicle_pages.gd` 构建功能页，`chronicle_map.gd` 绘制两层地图。默认会话使用 `scripts/campaign/campaign_service.gd`，正式战斗由 `battle_view.gd` 装配 `scripts/battle/battle_session.gd`，通过请求与结果交接；`stage_director.gd`按 `stage_catalog.gd` 的配置管理时间、刷怪和Boss门槛，表现另在 `battle_canvas.gd`。`chronicle_session.gd`／`chronicle_battle.gd` 仅保留为完整UI回归夹具。新模块清单及实现范围见[夺寨段实施记录](implementation/2026-10-27_夺寨聚众四关接入.md)。下表是保留的旧版战斗模块。


| 入口 | 当前职责 |
| --- | --- |
| `scripts/main.gd`、`scripts/player.gd` | 战斗与玩家协调层，仍包含较多状态及桥接。 |
| `scripts/game/session_state.gd`、`game_session_flow.gd` | 暂停原因、会话视图、结束与离开场景。 |
| `scripts/game/enemy_spawn_flow.gd`、`enemy_defeat_flow.gd` | 当前刷怪、死亡、奖励和Boss事件。 |
| `scripts/game/reward_flow.gd` | 旧升级、祝福、天赋槽与Boss奖励的连续流程。新人物卡奖励已在 `scripts/campaign/` 实现，不经过此入口。 |
| `scripts/player/player_level_flow.gd`、`player_build_system.gd`、`player_skill_level_system.gd` | 旧独立技能点、解锁、技能等级与分支/天赋槽。 |
| `scripts/player/player_equipment_flow.gd`、`ruan_stone_system.gd` | 旧角色装备及无尽永久物品，不能直接等同于新固定槽装备。 |
| `scripts/player/roles/*_role.gd`、`scripts/abilities/*_ability.gd` | 角色普攻、能力行为与数值。 |
| `scripts/player/player_damage_resolver.gd`、`player_damage_job_queue.gd` | 玩家对敌人的统一伤害和延迟结算入口。 |
| `scripts/enemies/enemy_damage.gd`、`scripts/player/player_survival_flow.gd` | 敌人受伤、玩家受伤与生存。 |
| `scripts/ui/hud/`、`scripts/ui/team_swap_panel.gd` | 当前HUD、人物面板及旧三人编队界面。 |
| `scripts/game/run_save_flow.gd`、`scripts/save/run_payload_validator.gd` | 运行档恢复、校验与失败传播。 |
| `scripts/player/player_run_save_state.gd` | 玩家运行态保存/恢复。 |

故事、存档和结算的数据流见[职责与数据流](09_脚本职责树与关键数据流.md)。

## 后续实施注意

- 新设计已经授权改变玩法，不能用“保持旧成长入口”作为架构限制；具体实施仍需对应明确的任务。
- 尽量复用有清楚职责的模块。新架构提案将内容定义、人物状态、战斗尝试、能力／伤害、关卡与主线提交分开；模块划分尚待可玩段落验证，不能仅把主控拆成仍随意改写同一个 `owner` 的静态流程。
- 定义、运行状态和只读显示分开；查询不顺手初始化状态，修复放在写入或加载边界。
- 继续保护统一伤害、对象池生命周期、奖励幂等、存档故障处理和暂停所有权。
- 旧架构测试可能包含将被替代的玩法假设。修改对应实现时同步合同，不将旧测试通过当作新玩法通过。
- 代码改动后的检查按根 [AGENTS.md](../AGENTS.md)执行；现存图谱限制见 [GRAPHIFY.md](GRAPHIFY.md)。

战斗表现入口为 `battle_art.gd`（素材映射）、`battle_canvas.gd`（已有场景与特效适配）、`battle_hud.gd`（已有HUD组件适配）。它们位于 `scripts/ui/chronicle/`，读取新会话，不实例化旧Player／敌人AI。见[表现复用记录](implementation/2026-10-27_战斗表现与HUD复用.md)。

HUD双布局由`battle_hud.gd`装配：`battle_hud_simple.gd`默认简单底栏，`battle_hud_team.gd`保留三行显示。两者读取同一BattleSession，设定／暂停复用`GameSettings.hud_layout`；不更换会话。
