# 工程架构与代码入口

## 基本信息

- 引擎基线：Godot 4.6.2
- 主运行场景：`res://scenes/main_menu.tscn`
- 配置文件：`project.godot`

## 目录结构

- `assets/`：测试图片、音频和临时素材。
- `effects/`：剑士、枪手、法师、机械师技能特效场景。
- `scenes/`：主菜单、战斗场景、HUD、玩家、敌人、拾取物等场景。
- `scripts/`：运行逻辑。
- `scripts/game/`：战斗场景 flow，负责刷怪、奖励、HUD、地图、存档和 session。
- `scripts/player/`：玩家模块，负责角色、祝福、技能、普攻、大招、数值、存档和奖励应用。
- `scripts/enemies/` / `scripts/enemy/`：敌人行为、属性、状态、掉落、Boss 行为。
- `scripts/combat/`：共享战斗规则；当前包含护甲伤害倍率计算。
- `scripts/ui/`：通用 UI、HUD 面板、升级详情、存档界面。
- `docs/`：当前项目文档。

## 主要场景

- `scenes/main_menu.tscn`：主菜单。
- `scenes/main.tscn`：战斗主场景。
- `scenes/player.tscn`：玩家节点。
- `scenes/enemy.tscn`：敌人节点。
- `scenes/hud.tscn`：战斗 HUD。
- `scenes/level_up_ui.tscn`：升级和奖励菜单。
- `scenes/pause_menu.tscn`：暂停菜单。

## 主要脚本职责

- `scripts/main.gd`：战斗主控和 flow 装配，不应继续堆具体玩法细节。
- `scripts/player.gd`：玩家节点协调层，保留必要状态和桥接函数；新增玩法优先放入 `scripts/player/*` 模块。
- `scripts/player/player_build_system.gd`：四角色构筑定义、技能解锁/升级与兼容应用；正式成长由角色独立技能点驱动，旧四选二构建器不是玩家入口。
- `scripts/player/player_skill_level_system.gd`：普通技能线 1~10 级，以及已有 LV0~9 专属构筑的等级、分支与存档规范化；`ROLE_PROGRESS_ORDER` / `PROGRESS_TITLES` / `UNLOCKABLE_PROGRESS` 是成长标识的来源。
- `scripts/player/data/mechanic_skill_talent_catalog.gd`：机械师 16 个专属技能槽位的名称、文案和参数常量；等级系统提供选卡与定义查询，角色和 ability 读取槽位所有权执行效果，不新增第二套保存状态。
- `scripts/player/player_skill_level_effect_flow.gd`：按当前技能等级提供剑士、枪手、法师、机械师的实际数值和升级预览；机械师登场/主动机炮通过部署来源分开读取等级。
- `scripts/player/player_skill_talent_system.gd`：角色天赋查询、规范化与兼容分发层；玩家等级每 3 级的发牌入口已停用（`pending_level_talent_choices` 不再累积），`LEVEL_TALENT_DEFINITIONS` 与 `has_level_talent()` 读取链保留待重新设计；纯定义已分到 `scripts/player/data/role_talent_catalog.gd` 与 `legacy_skill_talent_catalog.gd`，原接口只保留别名与兼容 helper。
- `scripts/player/player_blessing_system.gd`：通用祝福定义、祝福发牌委托和应用规则。
- `scripts/player/player_blessing_skill_state.gd`：祝福驱动的技能解锁、技能数量、持续时间和连段倍率。
- `scripts/player/player_level_flow.gd`：每次角色升级分配独立技能点、技能点解锁/升级与小 Boss 奖励入口。
- `scripts/player/player_upgrade_applier.gd`：当前奖励分发器，处理角色构筑、祝福、装备、小 Boss 训练、遗留最终核心 ID 和空选项；当前最终 Boss 菜单只发放胜利结算用的空选项，未接入三种最终核心。
- `scripts/player/player_equipment_flow.gd`：角色道具持有、转赠和装备数值。
- `scripts/player/roles/*_role.gd`：四名角色的普攻和角色差异。
- `scripts/abilities/*_ability.gd`：独立技能的战斗行为。
- `scripts/game/reward_flow.gd`：升级 UI、祝福绑定、技能 5 级天赋位二选一、小 Boss 奖励和最终奖励的串行流程桥接。
- `scripts/game/enemy_spawn_flow.gd`：地图边界内波次刷怪和警告。
- `scripts/game/game_hud_flow.gd`：HUD 数据投影。
- `scripts/game/session_state.gd`：场景内暂停原因合并与只读会话视图；`game_session_flow.gd` 协调继续、结束、保存失败和离开场景。HUD与配乐读取同一个模式/阶段/结果/目标视图。
- `scripts/save/run_payload_validator.gd`：恢复前验证直接消费的嵌套类型、数值与坐标；`run_save_flow.gd` 负责传播恢复结果，失败不能写回半恢复状态。
- `scripts/ui/hud/combat_skill_bar.gd`：两种 HUD 的布局、数据转发、悬停和拖拽；`scripts/ui/hud/widgets/` 中的五个 Control 独立拥有冷却、buff、头像、能量与角色行绘制，动画只在可见且需要时逐帧运行。
- `scripts/ui/hud/character_panel.gd`：角色面板、技能等级与天赋位、祝福、道具显示和转赠入口；技能页只读展示已保存的 `level_talents`，不启用其授予入口。
- `scripts/ui/team_swap_panel.gd` / `scenes/UI/team_swap_panel.tscn`：营地整备台与主线准备界面共用的换人面板；左列当前队伍、右列候补，提供定位/属性预览、替换与相邻重排；检查写盘成功才发布 `team_order`，失败回滚，队伍恒 3 人且不重复。

- `scripts/camp/endless_camp.gd`：世界交互与面板/移动状态协调、阵容形象及驻营同步、出击/教学/菜单导航。
- `scripts/camp/camp_shop_panel.gd` / `camp_shop_service.gd`：分类物品详情与购买/退还界面，以及先写盘后发布的交易；价格与效果仍由 `ruan_stone_system.gd` 提供。
- `scripts/camp/camp_overview.gd` / `camp_role_panel.gd` / `camp_environment.gd`：营地状态概览、四角色介绍与现有像素资源场景。

## 架构护栏

- 不把新玩法直接堆进 `player.gd` 或 `main.gd`。
- 新系统先判断归属：`scripts/player/*`、`scripts/game/*`、`scripts/ui/*`、Autoload，或纯数据 helper。
- 祝福、技能、装备、刷怪、HUD、角色面板必须保持模块边界。
- 技能等级与构筑 getter 只读状态，不扫描玩家属性表、不初始化或修复存档；修复与规范化在写入/加载边界完成。
- 纯定义归属数据目录；停用定义的保留不意味着正式奖励入口已恢复。
- 普通升级给每名队员各加1技能点；已有技能直接加点，空槽三选一解锁，波末祝福另行免费结算。新内容沿现有来源登记，不新增平行进度入口。
- 主动技能实例映射复用 `player_skill_cooldown_flow.ROLE_ACTIVE_SKILL_PROPERTIES`，手动分发与HUD读取同一表；当前参数由 ability 的真实 getter 提供。
- 敌人作者配置通过 `enemy_archetype_database.PROFILE_PATHS` 校验，未知ID不得默认为追击怪；只有旧档恢复入口允许兼容回退。
- `scripts/tests/check_architecture_contract.py` 用于检查核心边界。

## 伤害结算入口

玩家对敌人的伤害统一经过 `scripts/player/player_damage_resolver.gd` / `player_damage_job_queue.gd`，敌人受伤结算集中在 `scripts/enemies/enemy_damage.gd`。敌人对玩家的伤害统一进入 `scripts/player/player_survival_flow.gd`。双方顺序一致：总伤害 → 护甲防御 → 易伤乘区（1 + 易伤率）→ 减伤乘区 → 扣血。
