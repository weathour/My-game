# 技术债、风险点、重构建议

2026-10-25架构整改的范围、逐项验收和残余边界见[实施记录](implementation/2026-10-25_架构健全性整改.md)。维护时优先保持以下合同，再按真实瓶颈决定是否继续拆分。

- 文件保存成功不等于运行态恢复成功；先验证将被直接消费的类型/坐标，再显式传播恢复结果，失败不能自动重写主档与备份。
- 场景负责释放从树中移除的对象池成员。延迟命中同时核对实例与激活代数，不能把复用节点当作原目标。
- 分帧与视觉降级不能删除有效伤害或缩短出生预告。性能证据同时记录帧时间、队列等待与玩法计数。
- 主动技能实例对应表、成长ID、敌人资源清单分别复用现有权威；HUD当前参数读取运行getter，新增内容由遍历清单的契约检查发现漏接。
- 暂停只由场景会话层合并原因；观察者使用只读会话视图，敌人配置完成后才发布可观察身份。

## 高风险区域

- `player.gd`：仍是玩家状态和战斗桥接中心，新增功能不能继续堆在这里。
- `main.gd`：战斗主控仍较重，新增流程应进入 `scripts/game/*`。
- 祝福系统：祝福数据、技能解锁、角色面板、存档和 HUD 都依赖同一份状态。
- 特效和命中判定：大量敌人同时被多段技能命中时可能造成掉帧。
- 存档兼容：旧字段迁移和当前祝福/装备状态需要持续验证。
- 成长迁移：`player_skill_talent_system.gd` 仍保留角色天赋（入口已停用）、旧节点兼容与技能等级天赋分发；角色天赋和旧 108 节点的纯定义已分别抽到 `scripts/player/data/`；在决定删除、归档或恢复前，任何修改都必须先区分各套状态。
- 成长边界：人物页已只读展示 `level_talents`；它不代表授予入口已恢复。旧 `get_selected_talents()` 链仍停用。
- 技能等级内容与平衡：四角色均已由 `player_skill_level_effect_flow.gd` 提供成长；机械师八条线与 16 个专属天赋已补齐，其他角色槽位仍为占位。机械师本轮允许偏强、不做平衡调参；整局密度和压力仍需独立验证。`apply_level_effect()` 是预留事件钩子，不能用它为空推断所有等级无效。
- UI 职责拥挤：`level_up_ui.gd` 混合奖励类型、卡牌构建、刷新与输入；`combat_skill_bar.gd` 已把冷却、buff、头像、能量和角色行绘制拆为独立控件，保留两套布局、悬停和拖拽协调。后续按实际变更需要拆分，不按行数机械拆文件。
- 教程漂移：错误的退场技说明已修正；角色参数和按键仍含静态文本。

## 本轮营地修复边界

返营只清理局内运行档；17 种永久物品统一预览，购买/退款检查写盘结果。场景控制器已分离交易、商店、概览、角色介绍和环境绘制；铁匠复用装备分类，四角色均有驻营展示。阵容与首发编辑用于下一局，继续战局使用保存的阵容、加载当前携带。无购买历史，无法自动追补旧版本已清掉的物品。

修改营地继续跑 `endless_camp_smoke.gd`、`team_swap_smoke.gd`、`ruan_stone_profile_smoke.gd`、`ruan_stone_ui_smoke.gd`、`endless_progression_smoke.gd` 和完整项目检查；实机截图见营地评审。长期经济、打造树和新货币不属于本次修复。

## 当前护栏

- 后续新增进度内容必须明确进入角色构筑、祝福、技能等级与天赋位、角色天赋（待重新设计）或装备模块。
- 祝福数据只放在 `player_blessing_system.gd`。
- 技能解锁和技能倍率只放在 `player_blessing_skill_state.gd`；玩家节点暴露给 UI/战斗的祝福技能桥接放在 `player_blessing_skill_bridge.gd`。
- 装备奖励只放在 `player_equipment_flow.gd`。
- 小 Boss / Boss 奖励流程放在 `reward_flow.gd` 和对应 player applier。
- HUD 显示通过 `game_hud_flow.gd` 和 HUD 子组件，不从玩法代码直接拼 UI。
- 玩家每帧计时、临时状态过期和开发者无冷却逻辑由 `player_timer_flow.gd` 维护，`player.gd` 只保留兼容入口。
- 玩家视觉/特效创建逻辑应继续下沉到 `player_authored_effects.gd` 和 `player_effect_primitives.gd`；`player.gd` 只保留旧调用方需要的薄包装。
- 技能等级与构筑查询不得补写状态；写入/加载负责初始化与规范化。控件自身管理可见性与动画处理，布局销毁前必须清理拖拽等交互状态。
- 技能等级与天赋位只写入 `role_special_states[role_id].skill_levels` / `.skill_talent_slots`；角色天赋只写入 `level_talents` / `level_talent_group_locks`；旧 `skill_talents` 不得重新成为隐式第二套存档源。

## 新功能落点

- 新祝福：`scripts/player/player_blessing_system.gd`。
- 新祝福技能：`scripts/player/player_blessing_skill_state.gd` + `scripts/abilities/*_ability.gd`；若需要新增玩家侧 UI/提示入口，再扩展 `player_blessing_skill_bridge.gd`。
- 新角色普攻：`scripts/player/roles/*_role.gd`。
- 新装备：`scripts/player/player_equipment_flow.gd`。
- 新奖励流程：`scripts/game/reward_flow.gd`。
- 新刷怪规则：`scripts/game/enemy_spawn_flow.gd` 或 `scripts/enemy/enemy_director.gd`。
- 新角色面板信息：`scripts/ui/hud/character_panel.gd`。
- 新技能等级效果：`player_skill_level_effect_flow.gd` + 运行时消费点/预览 + 存档回归。新天赋位内容通过 `player_skill_level_system.gd` 的天赋位定义及 `has_talent_slot()` 进入消费点；不要把持续数值重复写入 `apply_level_effect()`。
- 新角色天赋（若要重新启用）：`scripts/player/data/role_talent_catalog.gd` 的 `LEVEL_TALENT_DEFINITIONS` + 对应运行时消费 flow + 新的触发入口；不要新增旧 108 节点。

## 验证建议

- 修改祝福后跑 `player_blessing_system_smoke.gd`。
- 修改运行中存档、装备、祝福、角色生命/法力或临时 buff 字段后跑 `player_save_roundtrip_smoke.gd`，确认 `get_save_data -> apply_save_data -> get_save_data` 不丢状态。
- 修改架构边界后跑 `check_architecture_contract.py`。
- 修改 GDScript 后跑 Godot headless parse。
- 修改角色面板或奖励 UI 后至少手动检查一次升级菜单、小 Boss 奖励和 C 面板。
- 修改技能等级或技能天赋位后跑 `player_skill_level_system_smoke.gd`、`content_growth_contract_smoke.gd`、`player_blessing_system_smoke.gd`、`character_panel_ui_smoke.gd`、`reward_flow_talent_smoke.gd` 和 `player_save_roundtrip_smoke.gd`；同时验证独立技能点、空槽三选一、已有技能加点与天赋位选择。
- 修改角色天赋（`LEVEL_TALENT_DEFINITIONS`）后跑 `player_skill_talent_system_smoke.gd`、`developer_skill_talent_smoke.gd` 与 `player_save_roundtrip_smoke.gd`。
- 修改切人规则或教程后同时检查 `EXIT_SKILLS_ENABLED`、离场角色能量消费、登场技触发和教学文字。

## 不建议

- 不建议把废弃设计文档里的机制重新搬回运行代码。
- 不建议为了短期实现把技能逻辑直接写进 `player.gd`。
- 不建议让 UI 文案和实际数值分离。
- 不建议绕过 `player_upgrade_applier.gd` 直接在 UI 里改玩家状态。
