# 重构边界与风险

2026-10-27更新。新界面已接前两关真实战斗，基础状态、能力与保存边界已落地；范围见[实施记录](implementation/2026-10-27_前两关真实战斗接入.md)。新设计见[共识](00_当前设计共识.md)，旧战斗差距见[基线](implementation/2026-10-26_重构前运行基线.md)，方案来源见[架构提案](design-reviews/2026-10-27_真实战斗架构与参考实现.md)。

## 先确定语义，再确定数据结构

后续实现需遵循已定语义：全部已获得人物、战役允许配置的人物和本关主角加两辅助分别表达；随行无人数上限。持有加成与后台支援分开，人物等级自动解锁技能，关间保留资源和阵亡，泉水或返营恢复。两层地图、进关快照、成功成果与主线行动结算分别处理；不保留容量扩充或满员驱逐需求。

不需要先为所有角色设计技能表，但不能把旧的“三个平等槽位”或“局内技能等级”字段换个名字就当作新模型。

## 主要风险

| 风险 | 后续需要检查 |
| --- | --- |
| 失败仍留下本关收益 | 人物经验、掉落、装备及额外奖励的所有写入来源；旧永久拾取到账不能提前提交。 |
| 辅助阵亡被关间刷新清除 | 阵亡状态保存、全角色换人时的可用性限制、泉水和返营恢复入口。 |
| 地图切换错误推进或重置 | 天下图查看不消耗行动；区域进度与小关成果保留，失败重试不扣主线行动；整次出征只结算一次。 |
| 持有加成重复累积 | 收卡、重复卡升级、换编队、读档后由同一份已提交人物数据推导。 |
| 重复结算或奖励丢失 | 成功、抽卡、入库、推进之间的中断恢复；尤其检查反复退出/加载。 |
| 旧成长入口仍然可达 | HUD加点、等级事件、奖励队列、开发者入口、兼容反序列化及教程文案。 |
| 旧测试误作验收 | 将旧行为事实与新规则分开，按实际改动更新合同，保留故障和生命周期检查。 |
| 直接堆大角色库 | 先验证主角、两辅助与一关的完整循环，再扩充内容。 |
| 数值跨主线失控 | 持有加成、角色等级、装备和限时经验的共同增长；具体曲线尚未批准。 |
| 拆文件后仍共享全部可变状态 | 旧静态流程通过 `owner` 改写主对象，通用伤害依赖各角色天赋；新人物应通过定义及能力扩展，不继续扩大中心对象。 |
| 切人改变已发出攻击的身份 | 弹体、命中、装备继承资格绑定来源人物及施放实例；场上身体不作为长期人物状态的唯一载体。 |
| 渲染预算影响胜负先后 | 旧伤害队列按渲染帧及耗时分批处理；正式战斗需明确逻辑结算顺序、Boss结束边界和池对象身份，再复用批处理。 |

## 可以保留的工程经验

统一伤害入口、数据与状态分离、暂停原因所有权、奖励幂等、原子主备保存、坏档恢复、对象池清理和激活代数检查，仍有独立价值。旧模块可以复用，不要求保留其全部玩法接口；也不因更换玩法而重写已经验证的底层保护。

## 当前未解决的问题

小Boss奖励恢复后二次退出丢失候选、高密度完整场景性能超预算、Graphify缺少GDScript提取器，仍是现有版本事实。详见[已知问题](KNOWN_ISSUES.md)。本轮没有修复这些代码问题，也没有启动它们的独立工作流。

当前新正式档采用独立目录和作用域，保留旧档与界面演练档。是否提供历史档迁移仍未决定，不能因此清除玩家存档。新核心目前限制敌人数并使用有界遍历，扩展更高密度时需重新测量；旧版高密度问题不因新两关通过而关闭。
