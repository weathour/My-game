# survivor-like 文档索引

`01`—`12` 记录当前规则、架构、风险和验证边界；`13` 是历史会议台账，含整理提交 `478ead1` 的非权威对照快照；`14` 保留已停用的 108 节点内容规格。当前正式成长是“四选二普通升级 + 玩家等级每 3 级一次角色天赋”，不是技能构筑 Lv.3/Lv.6/Lv.9 三阶段树。无尽模式按 N1→N∞ 逐层解锁，每层 Lv.1 重开，`12:00` 最终 Boss 到场，击败后才结算；骨头与阮狗五石永久保留。

当前文档规范统一写“法师”（`role_id=mage`）；`13`、`14` 的历史规格保留旧称“术师”。当前源码的个别等级天赋摘要和营地占位交互仍残留“术师”，已列入已知文案问题。

根目录 `PRODUCT.md` 与 `DESIGN.md` 分别记录产品目标、反例边界和暗金“构筑档案”视觉系统。当前角色面板展示普通构筑与祝福，但尚未展示真正生效的 `level_talents`；实现新 UI 前应先保持这两份约束一致。

重要玩法分析和设计变更先遵循 `15_游戏设计全景分析与评审流程.md`，并在 `docs/design-reviews/` 中建立带版本、证据、决定和验收标准的评审记录。

## 使用建议

- 查项目怎么跑：看 `02` 和根目录 `README.md`。
- 查战斗现在怎么工作：看 `03`。
- 查升级、祝福、技能解锁：看 `04`。
- 查关卡、Boss、难度：看 `05`。
- 查 UI、角色面板、存档、音频：看 `06`。
- 查当前进度和下一步：看 `08`。
- 查当前四选二、每 3 级等级天赋、互斥和存档：看 `04` 与 `08`。
- 查会议目标、历史 `221` 路径和延期/否决项：看 `13`；它不是当前实现说明。
- 查三角色 108 个旧规格节点、命名和质变后升级设计：看 `14`；当前正式玩家不可达。
- 查如何分析一个玩法问题、组织设计评审、形成设计合同和验收：看 `15`，再复制 `docs/design-reviews/TEMPLATE.md`。
- 查性能优化、掉帧原因和验证方式：看 `12`。
- 查代码职责和数据流：看 `09`。
