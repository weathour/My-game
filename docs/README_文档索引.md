# survivor-like 文档索引

`01`—`12` 记录当前规则、架构、风险和验证边界；`13` 是历史会议台账；`14` 保留已停用的 108 节点规格。当前正式成长规则为角色每升一级获得 1 个技能点，点击已有技能或普通攻击图标上方的“＋”直接升级；空技能槽的“＋”提供当前角色尚未拥有技能的三选一，不包含通用祝福。旧普通四选二入口已停用。技能等级天赋与角色总等级技能点分开处理。无尽模式按 N1→N∞ 逐层解锁，每层 Lv1 重开，每局20波，第6/11/16/20波为Boss波，波间30秒整备，击败最终Boss后结算。

当前文档规范统一写“法师”（`role_id=mage`）；`13`、`14` 的历史规格保留旧称“术师”。正式技能卡、已保存角色天赋摘要和营地提示已统一；旧节点规格与资源路径保留原命名。

根目录 `PRODUCT.md` 与 `DESIGN.md` 分别记录产品目标、反例边界和深林绿/酒红、古金雕花的战役界面视觉系统。当前人物页分为总览、技能、祝福和装备四页，右侧固定展示属性来源或条目详情；技能页只读展示已保存的 `level_talents`，其授予入口仍停用。2026-10-26 的[战役界面与音乐鉴赏评审](design-reviews/2026-10-26_战役界面与音乐鉴赏.md)记录本轮视觉参考边界、主页音乐入口、已完成的图形/集成检查和剩余验收边界。

重要玩法分析和设计变更先遵循 `15_游戏设计全景分析与评审流程.md`，并在 `docs/design-reviews/` 中建立带版本、证据、决定和验收标准的评审记录。

**接手当前工作，先读 `08_当前实现状态与后续重点.md`**，再结合工作区改动与相关设计评审核对本轮范围；验证入口见根目录 `CONTRIBUTING.md`。

当前架构整改的逐项实施、回归与性能边界见[2026-10-25架构健全性整改](implementation/2026-10-25_架构健全性整改.md)。

本轮已实装的系统框架、验证日志和剩余发布条件见[2026-10-23实施记录](implementation/2026-10-23_系统框架实施.md)。主线“等一声回答”的场景、物件入口、短句与旁白呈现见[2026-10-25评审](design-reviews/2026-10-25_主线场景与叙事呈现.md)，该记录区分自动检查、图形检查与待做玩家实玩。

当前美术接线、三关与正式遭遇、玩法健全性及下一章内里程碑见[美术关卡与配乐评审](design-reviews/2026-10-25_美术关卡与配乐制作推进.md)。14份原创配乐及REAPER/MIDI/母带、制作研究与技术QA见[配乐制作记录](../design/music-20261025/README.md)；只做音乐，不做台词配音。

## 使用建议

- 查项目怎么跑：看 `02` 和根目录 `README.md`。
- 查战斗现在怎么工作：看 `03`。
- 查升级、祝福、技能解锁：看 `04`。
- 查关卡、Boss、难度：看 `05`。
- 查 UI、角色面板、存档、音频：看 `06`。
- 查当前进度和下一步：看 `08`。
- 查当前技能点、波末祝福、技能等级与天赋位、互斥和存档：看 `04` 与 `08`。
- 查会议目标、历史 `221` 路径和延期/否决项：看 `13`；它不是当前实现说明。
- 查三角色 108 个旧规格节点、命名和质变后升级设计：看 `14`；当前正式玩家不可达。
- 查如何分析一个玩法问题、组织设计评审、形成设计合同和验收：看 `15`，再复制 `docs/design-reviews/TEMPLATE.md`。
- 查性能优化、掉帧原因和验证方式：看 `12`。
- 查代码职责和数据流：看 `09`。
- 查故事当前实现：看 `10`；查对话、道具、任务与剧情推进的架构合同：看 `16` 和2026-10-23评审；查本轮场景与文本呈现：看2026-10-25评审。
