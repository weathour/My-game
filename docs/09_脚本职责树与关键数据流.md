# 脚本职责树与关键数据流

## 战斗主控

- `scripts/main.gd`：战斗场景主控和 flow 装配。
- `scripts/game/game_scene_wiring.gd`：创建并连接 HUD、升级 UI、暂停菜单、角色面板等 UI。
- `scripts/game/game_hud_flow.gd`：把战斗状态投影到 HUD。
- `scripts/game/game_character_panel_flow.gd`：角色面板打开、关闭和暂停规则。
- `scripts/game/session_state.gd`：合并场景内暂停原因，提供只读会话视图。菜单/奖励/人物页只释放自身原因，音乐与HUD不各自猜测模式和胜负。
- `scripts/game/blessing_unlock_notice_flow.gd`：技能解锁/进化消耗祝福材料时的短提示弹窗。
- `scripts/game/reward_flow.gd`：升级、祝福绑定、技能天赋位二选一、小 Boss 奖励和最终奖励流程；它是连续奖励菜单的唯一调度者。
- `scripts/game/enemy_spawn_flow.gd`：波次刷怪和刷新警告。
- `scripts/game/enemy_defeat_flow.gd`：敌人死亡后的奖励、成就和 Boss 流程。
- `scripts/game/difficulty_profile.gd`：从 N1 简单锚点与 N11 地狱锚点生成无尽层级数值。

## 玩家模块

- `scripts/player.gd`：玩家节点协调层。
- `scripts/player/player_build_system.gd`：角色构筑定义、技能解锁/升级数据及构筑应用；旧四选二构建器保留兼容，正式入口由独立角色技能点驱动。
- `scripts/player/player_skill_level_system.gd`：普通技能线 1~10 级、剑士普攻 LV0~9 阶段选择、等级效果接入点与存档规范化。
- `scripts/player/data/mechanic_skill_talent_catalog.gd`：机械师 16 个专属槽位定义与数值常量；`player_skill_level_system` 生成真实选卡，`mechanic_role` / 五个 ability 在原所有者内消费 `has_talent_slot`，高爆由 `bullet` 的一次性命中效果结算。
- `scripts/player/player_skill_level_effect_flow.gd`：技能等级的数值成长和升级预览，运行时读取当前等级，避免读档重复叠加。
- `scripts/player/player_skill_talent_system.gd`：角色天赋（`LEVEL_TALENT_DEFINITIONS`）定义、互斥组、选择校验和存档规范化。玩家等级每 3 级的待选队列已停用（`pending_level_talent_choices` 不再累积），定义与 `has_level_talent()` 读取链保留待重新设计；角色天赋纯定义归入 `scripts/player/data/role_talent_catalog.gd`；旧 18 树/108 节点、名称/路径投影归入 `legacy_skill_talent_catalog.gd`，其正式队列、应用和查询接口同样停用。
- `scripts/player/player_blessing_system.gd`：7 种正式通用祝福、legacy 祝福与魔石定义，以及当前只过滤 `CATEGORY_GENERAL_BLESSING` 的发牌委托和应用。
- `scripts/player/player_blessing_skill_state.gd`：祝福配方、材料锁、技能绑定和技能倍率；当前主动技能配方依赖的 legacy 材料不由正式奖励生成器发出。
- `scripts/player/player_blessing_skill_bridge.gd`：玩家节点上的祝福查询、绑定选择和技能事件提示桥接。
- `scripts/player/player_level_flow.gd`：升级请求、构筑发牌/刷新和小 Boss 奖励入口。
- `scripts/player/player_upgrade_applier.gd`：升级/奖励分发器。
- `scripts/player/player_equipment_flow.gd`：装备奖励、角色持有、转赠和装备数值。
- `scripts/player/ruan_stone_system.gd`：无尽档案中的骨头、按份购买/退款、携带上限与效果数值；当前每份 5 骨，携带上限为最高解锁 N。
- `scripts/player/player_ruan_stone_flow.gd`：识别三角色直接普攻事件，结算连锁、减速、毒伤、按死者最大生命计算的死亡爆炸和易伤，并阻止派生伤害递归触发。
- `scripts/player/player_skill_cooldown_flow.gd`：技能栏槽位数据，支持当前角色与指定角色的冷却槽构建。
- `scripts/player/player_timer_flow.gd`：玩家运行时计时器、临时 buff、技能冷却更新和开发者无冷却清理。
- `scripts/player/player_authored_effects.gd`：带动画场景的技能特效创建、播放、复用和释放。
- `scripts/player/player_effect_primitives.gd`：线条、圆环、爆发、护盾、文字等轻量特效创建、复用和释放。
- `scripts/player/player_run_save_state.gd`：运行中存档。
- `scripts/player/roles/*_role.gd`：四名 roster 角色的普攻和角色差异，单局队伍仍为三人。
- `scripts/abilities/*_ability.gd`：祝福技能的独立行为。

## UI 模块

- `scripts/level_up_ui.gd`：升级和奖励菜单。
- `scripts/hud.gd`：战斗 HUD。
- `scripts/ui/hud/character_panel.gd`：角色面板、技能等级与天赋位、祝福和道具展示；技能页显示 `技能 Lv.x / 10` 与两个天赋位状态。
- `scripts/ui/hud/combat_skill_bar.gd`：两套 HUD 的布局与输入协调；五类绘制对象位于 `scripts/ui/hud/widgets/`，自行管理动画生命周期。默认使用底部居中技能栏，也可按 `gameplay/hud_layout` 切换为三行队伍状态栈，固定展示 Q / 当前 / E 三个角色的 HP、MP 和 6 个技能冷却槽。
- `scripts/ui/components/*`：卡片、悬停详情和通用 UI 组件。

## 升级数据流

获得经验并升级后，`player_level_flow.handle_reached_level` 给每名队员各加1技能点，普通升级不自动弹菜单。HUD已有技能或普攻的“＋”直接升级；空槽“＋”生成当前角色未拥有技能的三选一。成功应用才扣该角色的点数，切人读取各自余额；选择与余额可以续档。

普通1~10级技能仍通过 `player_skill_level_system` 处理5级天赋位选择和10级补齐；已有LV0~9专属构筑走各自阶段分支。`reward_flow.gd` 串行处理待选内容；波末免费通用祝福不消耗技能点。旧四选二、每3级角色天赋发牌与108节点入口均停用，不从旧构建器推断玩家可达性。

## 技能解锁与 legacy 配方数据流

正式角色构筑解锁卡
-> `player_build_system.gd`
-> `player_blessing_skill_state.force_unlock_skill()` 写入 Tier I
-> `player_skill_cooldown_flow.gd` 生成技能栏槽位
-> 对应 `scripts/abilities/*_ability.gd` 在战斗中触发

legacy/开发者祝福状态
-> `player_blessing_skill_state.gd` 检查配方解锁与进化，并在锁定材料的事件中写入 `material_lines`
-> `player_blessing_skill_bridge.gd` 处理绑定选择队列和事件信号
-> `blessing_unlock_notice_flow.gd` 显示材料锁定提示

正式新档奖励生成器不产出完成主动技能配方所需的 legacy 材料，因此第二条不属于当前玩家正式链路。

## 小 Boss 奖励数据流

小 Boss 死亡
-> `enemy_defeat_flow.gd`
-> `reward_flow.gd`
-> `player_level_flow.get_small_boss_reward_options`
-> `player_equipment_flow.get_active_reward_options`
-> `level_up_ui.gd`
-> `player_upgrade_applier.apply_upgrade`
-> `player_equipment_flow.apply_equipment_reward`

## 骨头与阮石数据流

敌人最终死亡
-> `enemy_drops.gd` 按无尽模式和敌人类型生成骨头拾取物
-> `player_survival_flow.gd` 吸附，`save_manager.gd` 同次保存骨头余额与当前run内的拾取ID凭据；成功后才移除拾取物，旧快照恢复不会重复入账
-> `camp_shop_panel.gd` 选择物品，`camp_shop_service.gd` 读取新档案副本并调用 `ruan_stone_system.gd` 按份购买/退款
-> `save_manager.gd` 原子写盘成功后才刷新商店与营地概览
-> 战斗开始由 `game_story_context_flow.gd` 把当前无尽档案投影到玩家运行时
-> 四角色的直接普攻（含机械蜘蛛）使用显式基础攻击事件来源进入 `player_damage_resolver.gd`
-> `player_ruan_stone_flow.gd` 按物品种类对一次事件去重，多份消费累计效果；派生伤害不递归触发

## 营地协调与界面

`endless_camp.gd` 只协调世界交互、最近提示、面板互斥/移动锁、阵容形象刷新与场景切换。`camp_overview.gd` 展示永久进度、阵容和携带；`camp_role_panel.gd` 从当前角色/技能定义生成驻营介绍；`team_swap_panel.gd` 验证替换与重排并检查写盘；`camp_environment.gd` 使用现有像素资源绘制地面与植被。商店展示、交易与持久化各有明确入口，不在场景控制器内重写物品数值。

## 无尽 N 层数据流

营地传送门
-> `endless_tier_overlay.gd` 只允许选择 `N1...最高通关+1`，有运行档时锁定为继续该层
-> `save_manager.gd` 写入 `selected_tier`
-> `game_story_context_flow.gd` 生成当前 N 层难度并创建 `run_id`
-> `run_save_flow.gd` 保存 `run_tier/run_id` 与本层局内构筑
-> 第20波最终 Boss 死亡、波末奖励完成后 `enemy_defeat_flow.gd` 请求结算
-> `save_manager.gd` 以 `last_rewarded_run_id` 幂等发放固定/首通骨头并推进 `highest_cleared_tier`
-> 同次永久档写入 `last_clear_summary`，`reward_flow.gd` 显示单一返营确认
-> `game_session_flow.gd` 清除当前运行档并返营，永久骨头与携带列表保留

## 存档数据流

`main.gd`
-> `save_manager.gd`
-> `player_run_save_state.gd`
-> 保存角色状态、祝福状态、技能祝福、技能等级与天赋位、角色天赋与互斥锁、持续技能运行态、装备和战斗进度。

读取运行中存档时，`player_run_save_state.gd` 先恢复角色列表、装备、属性训练和祝福状态，再按最终角色最大生命值归一化 `role_health_values`。技能等级与天赋位从 `role_special_states[role_id].skill_levels` / `.skill_talent_slots` 恢复；角色天赋从 `role_special_states[role_id].level_talents` 恢复，互斥锁由已选项补全/规范化；活动选择上下文只保留重建候选所需字段。旧 `skill_talents` 统一清空。

能力运行态以 `ability_runtime` 的技能ID保存，四角色20主动技能的冷却都有真实玩家往返回归，并兼容已有旧扁平键。持续效果、弹体和部署物只恢复各 ability 已明确序列化的状态；通用玩家 `Bullet` 节点与任意 scheduler 回调不属于完整战斗重放合同。骨头、阮石和最高 N 层属于无尽档案，不在玩家运行存档重复保存；本层玩家构筑及尚未拾取骨头只存在于 `run_tier/run_id` 对应的继续档。

## 开发护栏

- 新祝福先改 `player_blessing_system.gd`。
- 新祝福技能先改 `player_blessing_skill_state.gd`，再加 ability。
- 新奖励先判断是 `player_reward_applier.gd`、`player_equipment_flow.gd` 还是 `reward_flow.gd`。
- 新 UI 不直接堆进 `main.gd` 或 `player.gd`。
- 升级数据流以角色独立技能点为准；技能ID到能力实例复用现有 `ROLE_ACTIVE_SKILL_PROPERTIES`，成长ID复用 `UNLOCKABLE_PROGRESS`，不再复制另一份对应表。

## 故事与保存边界（2026-10-23）

- `story_content.gd` 读取 `assets/story/chapter1.json` 并按ID查询；`story_state.gd` 是不依赖SaveManager的验证/迁移层。
- `story_progress.gd` 接收模式/槽位约束下的命令，在副本上更新任务、物品、凭据与对话检查点，交给SaveManager提交。UI只在成功后刷新已提交状态。
- `dialogue_flow.gd` 维护当前对话视图；准备页和 `ui/story/` 使用共享弹窗、队伍整备和记录页。没有新增Autoload、通用事件总线或独立背包引擎。
- `SaveFileStore` 负责原子文件替换、上一版永久档备份及原始故障文件保留；`SaveManager.profile_status/run_status` 只读并区分健康状态；业务层显式决定恢复、重试或放弃。
- `RewardFlow` 持有连续奖励顺序与恢复上下文；`GameSessionFlow` 持有失败/放弃和场景离开顺序；`RunOutcome` 生成复盘数据。战斗主控继续只调用已有flow。
- 运行档恢复先经过 `run_payload_validator.gd`；坏主档可回退有效备份，运行对象恢复失败时不自动保存、不继续战斗，可安全返回菜单。无尽结算清理失败可重试，永久奖励按run身份防重。
- 敌人通过显式配置完成通知进入配乐观察；离树对象池由战斗退出清理。排队伤害携带目标激活代数，复用节点不会继承上一世的命中。
- `GameSettings` 共用配置缓存；暂停页直接嵌入主菜单设置组件。`ui_audio.gd` 提供短提示音，共享主题只绑定一次。

内容结构检查：`python3 scripts/tests/check_story_content.py`。状态、故障恢复和真实场景验收见[实施记录](implementation/2026-10-23_系统框架实施.md)。
