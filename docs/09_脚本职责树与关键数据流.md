# 脚本职责与关键数据流

2026-10-27：本页区分保留的旧代码与已实现的新战斗数据流。总入口见[工程架构](02_工程架构与代码入口.md)，目标见[当前设计共识](00_当前设计共识.md)。

## 旧战斗与成长

`main.gd` 装配战斗flow；`player.gd` 协调角色和能力。角色普攻位于 `scripts/player/roles/`，独立能力位于 `scripts/abilities/`。

经验升级经 `player_level_flow.gd` 分配各角色技能点，HUD加点或空槽候选进入 `player_build_system.gd` 和 `player_skill_level_system.gd`。普通技能天赋槽、部分专属分支及波末免费祝福仍按旧流程处理。旧四选二和更早的角色天赋树不因定义仍在就成为正常入口。

新设计用人物卡和人物等级替换上述成长入口。后续应一起审查等级、奖励、显示、保存与测试，不在旧卡片生成器上叠加另一套未分清边界的成长状态。

## 伤害与对象生命周期

玩家命中经 `player_damage_resolver.gd` / `player_damage_job_queue.gd`，敌人受伤经 `scripts/enemies/enemy_damage.gd`，玩家受伤经 `player_survival_flow.gd`。当前计算顺序包含护甲、易伤与减伤；它是旧代码事实，新数值体系尚未决定是否沿用。

敌人配置完成后发布身份；排队命中携带激活代数，避免对象池复用后击中另一代敌人。战斗退出负责释放离树对象池。新关卡切换不能丢掉这些生命周期保护。

## 奖励与会话

`enemy_defeat_flow.gd` 接收死亡事件，`reward_flow.gd` 组织奖励队列和恢复上下文，`game_session_flow.gd` 协调保存、结算与离开。场景内 `session_state.gd` 合并暂停原因；HUD、音乐读取同一会话视图。

新流程需要容纳额外精英收益、关末人物卡和本关成功提交。旧波末祝福、无尽结算和奖励上下文都需要重新映射。现有奖励恢复后二次退出问题见[已知问题](KNOWN_ISSUES.md)。

## 保存与剧情

`SaveFileStore` 提供临时文件替换、备份与故障文件保留；`SaveManager` 协调档案和运行档；`run_payload_validator.gd` 在恢复前检查直接消费的嵌套类型与数值。运行对象恢复失败时不能写回半恢复状态。

`player_run_save_state.gd` 与能力运行态承担玩家、角色、装备及能力的序列化。现有恢复不等于完整战斗重放：任意调度回调和所有弹体并非都能精确复现。

`story_content.gd` 读取 `assets/story/chapter1.json`；`story_state.gd` 验证/迁移；`story_progress.gd` 在副本执行任务、交付和检查点命令，再提交保存；`dialogue_flow.gd` 和 `ui/story/` 表达已提交状态。

新设计需要明确进关前快照、未提交收益、跨关人物状态和一次性成功结算。旧故事练习重访、每关成长边界及无尽拾取即时入账不能自动沿用。具体保存目标见[界面与存档](06_UI_菜单_存档_音频.md)。

## 2026-10-27 新战斗与主线

默认入口为 `scenes/chronicle/chronicle_shell.tscn`。页面 → `CampaignService` → 请求与进关快照 → `BattleSession` 工作副本 → 一次战斗结果 → 主线待结算／领取 → 原子保存。失败丢弃本次副本，不逆向修补旧玩家对象。

当前已接六个战斗节点及12人物（含主角）；S03之后B04／B05互斥，单次路线四场或含可选B06时五场。人物及能力由 `combat_catalog.gd` 定义，`stage_catalog.gd` 提供分时敌人组合、成组数量与上限、Boss攻击顺序和地图配置，`StageDirector` 按配置处理时序、刷怪和门槛。本轮新增四人在剧情或B06胜利后入池，不自动取得。

输入、自动普攻、常规技能及支援 → `AbilitySystem` → 施放时参数快照 → 命中／弹体 → `CombatResolver` → 死亡与经验 → `StageDirector` 门槛和终止。角色资源由 `CharacterRuntime` 保存，前台切换不重建资源。核心不读 UI 或主线磁盘档。

正式档使用 `chronicle_campaign_v1`，schema仍为1；读取已完成 S03／S04／B06 的旧正式档时按已完成节点补齐对应卡池，不赠送人物、不重掷已生成候选并保留选择。完整UI回归仍可显式注入 `ChronicleSession` 的演练夹具，两者数据与旧版保存流均隔离，不迁移演练档。边界与测试见[实施记录](implementation/2026-10-27_夺寨聚众四关接入.md)。

只读表现流：`BattleSession` → `battle_canvas.gd`／`battle_hud.gd` → 原人物／怪物视觉场景与HUD小组件；`battle_art.gd`集中素材映射。跟随视野只换坐标投影，战斗仍在固定逻辑坐标中运行。旧素材复用不经过旧角色成长或天赋流程。

HUD双布局由`battle_hud.gd`装配：`battle_hud_simple.gd`默认简单底栏，`battle_hud_team.gd`保留三行显示。两者读取同一BattleSession，设定／暂停复用`GameSettings.hud_layout`；不更换会话。
