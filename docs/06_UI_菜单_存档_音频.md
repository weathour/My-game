# UI、菜单、存档与音频

HUD 控件的具体信息在鼠标持续悬停 1.5 秒后显示。法师火焰之径激活期间，角色头顶显示随剩余激活时间缩短的图形进度条，不显示数字；切换角色、状态结束和读档恢复均同步处理。

角色技能点独立保存于玩家运行档`role_skill_points`（角色ID→余额）；`skill_points`接口与HUD均表示当前操控角色的余额。每升一级全队每名角色各加1点，加点只扣当前角色。旧档没有角色点数表时，将原公共剩余点数分别赋给队伍各角色，旧待升级次数同样各自补发；新档读回不会重复补发。切人后技能加号与高亮跟随该角色的可用点数。

## 波次与整备补给（2026-10-19）

- 波末依次播放残怪死亡消散动画（0.7秒）、全部晶体飞向角色并吸收、经验与升级结算，最后停留0.5秒再显示Build界面的免费通用祝福三选一；飞行期间不打开菜单或开始整备倒计时。选择只获得1个祝福，不消耗技能点。选卡时暂停战斗及整备倒计时。小Boss奖励也在经验收完后才显示，先处理小Boss奖励、再处理波末祝福；最终波选卡完成再进入结算。
- 波次运行档额外记录`blessing_pending`和完整`blessing_offer`；继续游戏恢复原来的三张候选，已经领取不会重复发放。玩家运行档不把本次免费选卡记为升级次数或技能点消耗。

- 生存/无尽HUD显示当前波数、波类型及战斗倒计时；Boss波显示击败Boss后进入整备。
- 每波收尾动画和经验吸收完成后进入30秒整备，剩余怪物清退不计击杀也不掉奖励，地上既有非经验奖励保留；停止自然刷怪，阮狗在玩家附近出现。靠近120距离内可打开补给，当前只有免费卡「急救：恢复所有人物已经损失血量的50％」，每轮整备只能领取一次；对全队每名角色分别计算，遵循现有治疗修正规则。收尾阶段、阶段计时与待处理小Boss奖励保存恢复，清退中的尸体不写入活怪存档，已吸收经验不会再次发放。
- 补给面板不暂停游戏，倒计时、敌人、弹道和技能继续运行。阮狗暂定200生命，可被敌人碰撞及普通敌方弹道击杀，死亡后本轮无法领取；原有小Boss奖励选择仍保留自己的暂停流程。
- 「跳过整备，进入下一波」在整备期间可用，打开补给也保持可见；点击后阮狗离开并立即开始下一波。30秒到期同样自动开始。
- 战斗存档新增 `combat_wave`，记录波数、阶段、已过时间、整备剩余时间、急救领取状态、阮狗生命/位置、Boss已登场、精英与飞眼事件进度。敌人保存波次Boss归属与飞眼掠袭状态。读档不重复领取急救，不复活本轮已死阮狗。
- 旧运行档没有波次数据时保留角色和残怪，从第1波接入；若场上已有对应Boss，则接管第6/11/16/20波，避免重复生成。

- 开发者普通怪列表新增亡灵牧师，模板上限2只，20波流程上限1只，生成在地图左右侧；玩家Buff栏新增亡灵印记及回血转扣血说明，印记时长和牧师技能冷却纳入战斗存档。

- 开发者普通怪列表新增藤蔓怪、幽影树怪、幽影树怪·幼年；玩家遭到藤蔓怪伤害后显示缠绕状态，缠绕只限制移动。植物怪技能冷却、树种飞行/落地孵化和寄生种子爆炸倒计时、玩家缠绕周期伤害纳入战斗存档。

- 开发者模式击杀怪物不掉落经验晶块，所有敌方类型共用此规则。

- 开发者模式的普通怪生成列表新增「骷髅法师」，模板上限4只，现已加入20波流程第13/19波并受波次上限约束。玩家攻击寒冰护甲期间的骷髅法师造成伤害后，Buff栏显示「寒冰侵蚀」；位于不洁领域内显示「不洁领域」，悬停可查看减攻速、减速和冷却规则。寒冰侵蚀、怪物技能计时/临时生命/死灵身躯已使用标记、独立领域位置和剩余时间纳入战斗存档。

剑刃风暴构筑支持LV0–9、LV4/8/9二选一，升级卡、角色面板和开发者菜单共用现行构筑定义。战斗存档保留施法时强化快照、龙卷位置/方向/剩余时间、风息剩余时间；敌方存档保留烈风每一层独立削甲计时，对象池复用时全部清除。

风息接入瞬杀同款战斗 Buff 栏，以青绿色“息”图标显示持续进度，悬停显示名称、完整属性加成和剩余时间；切换角色后继续显示，15秒到期自动消失，读档沿用保存的剩余时间。

## 开发者菜单（2026-10-02）
- 顶部固定“收起菜单”按钮，切换分类、滚动列表或打开敌人子菜单时始终可用。一键隐藏标题、内容与子菜单，仅保留“展开菜单”按钮；重新展开保留分类、搜索和选择。

- 四页：祝福、角色 build、商店物品、战斗调试。支持收起/展开、窗口自适应，列表和详情独立滚动。
- 祝福/物品数量操作保留搜索词、选中项与数量；未变化的数据刷新不重建列表。祝福阶级与份数分别设置，批量授予只覆盖当前正式通用祝福。
- 角色页使用队伍角色下拉选择，不切换玩家站场角色。剑士普攻显示当前倍率、实际攻速、间隔及三个阶段的完整效果；降低等级后立即清除超出等级的分支。
- 新信号 `developer_catalog_action_requested(Dictionary)` 经 HUD 与主场景送入 `developer_build_tools.gd`，统一验证内容和等级范围、刷新属性。旧祝福/等级天赋按钮与信号链已移除。
- 所有数量和 build 变更均为本局调试，沿用开发者模式禁止正式存档的规则，不增加正式存档字段。

## 主菜单视觉规则

- 当前首屏即主菜单
- 首页背景为原创 `assets/ui/campaign/four_heroes_menu.png`（1672×941），采用线性过滤与保持比例 cover；左侧留给实际导航，右侧绘出四位角色：金发马尾、蓝蝴蝶结与白披风剑士，红发枪手，银紫发法师，以及蓝发眼镜、红发带、卡其工装机械师。
- 四人身份参照当前 `assets/players/` 三位角色待机图与机械师正式设计母图 `design/mechanic-rework-20261013/source/character-master.png`；旧 `assets/demo2.png` 保留但主页不再引用。资产来源与创作边界见 `assets/ui/campaign/README.md`。
- 共享主题使用深林绿、酒红、暖象牙文字、金色衬线标题和原创古金雕花框。雕花框由 `campaign_frame.gd` 作为九宫拉伸 `Node2D` 装饰绘制，不占布局、不截获输入，也不把界面压成背景截图。
- 同一视觉合同延伸到准备/阅读/记录、人物页、存档选择、营地概览、HUD、暂停与奖励界面；各页原有信息层级、焦点、输入和存档行为保持。
- 框架和配色参考《兰斯10》官方系统页的视觉呈现，只借鉴构图、色彩和标题层级；本项目使用自有界面、文案、美术与玩法规则，不复用官方素材。

### 音乐鉴赏

- 首页“音乐鉴赏”可打开 `scripts/ui/main_menu/music_room.gd`，列出 `scripts/audio/music_catalog.gd` 当前收录的全部 14 首原创配乐，无解锁条件。
- 播放页提供曲目选择、上一首/下一首、播放/暂停、拖动进度条、当前/剩余时间与静音/音量状态；曲目自然结束后按目录顺序播放下一首。
- 打开时暂停菜单 BGM 并记住播放位置；试听沿用既有音乐音量、静音和总线。关闭时停止并释放试听播放器，恢复菜单原曲与位置，不叠加播放；Esc 返回首页并恢复焦点。
- 自动 smoke 覆盖曲目清单、切歌/播控、进度、音量/静音与菜单音乐恢复。主菜单与音乐鉴赏已检查 960×540、1280×720、1920×1080；截图、集成检查和验收边界见[战役界面与音乐鉴赏评审](design-reviews/2026-10-26_战役界面与音乐鉴赏.md)。

## 设置菜单

主菜单和暂停菜单都支持：

- 背景音乐音量滑条
- 背景音乐静音开关
- 性能日志记录开关（默认关闭，仅用于短时间排查卡顿）
- HUD 布局选择：默认“底部技能栏”，可切换到“三行队伍状态带”；存储 ID 仍为 `legacy` / `team_band`

主菜单设置面板实现：

- `scripts/main_menu.gd` 点击“设置”后调用 `settings_panel.open()`。
- `scripts/ui/main_menu/main_menu_settings_panel.gd` 根节点必须是全屏 `Control`，不能再依赖 `CenterContainer` 居中。
- 设置面板内部使用 `scripts/ui/core/survivors_modal.gd` 统一弹窗；打开和窗口尺寸变化时会重新 `apply_layout()`，保证弹窗居中且不贴角落。
- 三个设置分类共用一个原生滚动容器，类别按钮显示当前选中项；只保留设置总标题与当前页标题，关闭按钮固定在底部。
- 音量页含音量与有文字标签的静音开关；性能日志归入显示页。按键页覆盖全部可改键动作，键盘聚焦会自动滚动到目标。
- 打开设置后焦点进入分类栏，Tab / Shift+Tab 在面板内循环，关闭后恢复原焦点。Esc 优先取消待录入键位，再次按下关闭设置；切换分类也取消待录入状态。录入在 GUI 导航之前处理，因此 Tab / Enter / Space 可正常设为动作键。
- 共用弹窗保留入树前配置的标题/提示，空标题不占位；沿用现有中文阅读字体。设置、暂停和选层均复用此规则。


## 显示设置

当前主菜单设置面板包含显示设置页：

- 窗口模式：窗口 / 全屏
- 窗口大小：`1280x720`、`1600x900`、`1920x1080`
- HUD 布局：旧版底部技能栏 / 新版三行队伍状态带
- 窗口可拖拽调整，`WindowDisplayManager` 会将窗口尺寸校正为 `16:9`
- 显示配置合同使用 `canvas_items + keep`，避免非标准比例下画面被拉伸变形
- 显示配置要求有效值为 `window/size/resizable=true` 和 `window/stretch/aspect="keep"`。Godot 4.6.2 会省略这两个默认值；`check_project_config.py` 接受省略默认值，但仍拒绝显式写成其他值。
- `project.godot` 显式设置 `run/max_fps=120` 且关闭 VSync 帧率钳制，避免渲染被固定在 60 FPS，同时把最高渲染帧率限制在 120 FPS；物理 tick 仍按 Godot 默认 60Hz 运行。
- 显示设置保存于 `user://settings.cfg` 的 `display` section
- 性能日志记录设置保存于 `user://settings.cfg` 的 `gameplay/performance_trace_enabled`；开启后写入 `user://performance_trace_latest.jsonl`，包含周期样本和慢帧样本。
- HUD 布局设置保存于 `user://settings.cfg` 的 `gameplay/hud_layout`；默认值为 `legacy`。

## HUD

当前 HUD 方向：

- 常驻显示：时间、等级
- 核心显示：经验条、HP、MP / 大招能量
- Boss 出现时顶部切换为 Boss 名和 Boss 血条
- 最终 Boss「被污染的魔法石」仅在 9 秒瘫痪期间显示「瘫痪 · 护甲降低50」及倒计时条；基础战斗、破盾、预告、弹幕演出、激光预警、收尾和转阶段不显示状态文字或倒计时，血条、护盾与场景中的攻击预警保留。
- 默认底部战斗栏采用旧版居中布局：左侧为 `Q/E` 轮换头像和切换冷却，中间为固定 6 格技能冷却槽，右侧为当前角色大招能量；经验条与 buff 栏保留在技能槽附近。
- 可在设置中切换到新版横向三行队伍状态带：三行角色来自存档 `team_order` 决定的当前队伍，上行为 `Q` 上一位，中行为当前站场角色，下行为 `E` 下一位；每行显示对应角色的正式头像、HP、MP / 大招能量和固定 6 个技能冷却槽，未解锁槽位保留空格。头像圆环复用旧版切换反馈，分别显示该角色自己的切换能量，并叠加全队切换冷却遮罩。
- 新版布局中当前站场角色固定在中间，并通过更高行高、暗金边框、左侧发光竖线、整体右移和更亮技能格强调；待命角色保持较小尺寸和低亮度。
- 战斗栏上方的 buff 栏会显示临时状态；剑士登场后的“嗜血”使用蓝底单字“嗜”图标显示剩余时间
- 技能/普攻图标使用短标签保持 6 格技能栏比例；剩余冷却、完整技能名和说明放在鼠标悬停详情中，空槽悬停时显示预留说明。
- 技能悬停在技能栏上方展示所属角色、`Lv.x / 10`、自动/手动模式、说明和冷却；队伍状态带注明待命角色，悬停期间剩余冷却持续更新。定点机炮、重型炮台另列当前标准部署的伤害倍率、射击间隔与持续时间；不把倍率当成扣除防御后的命中伤害。其他技能继续使用能力对象已有说明，尚未全部改成实时数值表。
- 暗金详情使用独立浅色文字，不继承浅色卡面的黑色字；等级、数字、当前状态与操作提示分区。旧配方材料不占战斗悬停的主要阅读区域，原有后台配方数据仍保留。`level_talents` 不追加旧三阶段节点名，也没有路径码；已保存的角色天赋另在人物页技能栏目以只读清单展示。
- 数字键 `1`—`6` 是主动技能槽的快捷键（默认键位，可在设置的“键位设置”页改为任意键，技能槽 1—6 为独立可改键动作）。每个主动技能都有“自动释放 / 手动释放”两种状态，默认自动：自动状态下技能按原规则自行施放、快捷键不响应，槽位边框带顺时针循环的亮光提示；`Ctrl` + 槽位键或鼠标右键点击技能栏中的该技能槽可切换状态，手动状态下按快捷键立即施放（槽位键位数字高亮）。鼠标左键可拖动某个技能槽到同一角色的另一个技能槽交换位置，拖动时显示跟随光标的技能标签、放下后播放交换动画。该状态与槽位顺序都保存在全局设置（`user://settings.cfg`）中，与运行存档无关，所有存档共用；普攻槽与技能槽之间留出更大间距。
- 角色行悬停时显示该角色 HP、MP / 大招能量、切换能量和切换冷却，技能格悬停时显示对应角色的技能说明和剩余冷却。
- 小地图包含玩家、敌人、Boss、经验晶体和回复道具位置；宽窗口置于右下角，视口宽度低于 1280 时移至右上角。窄窗队伍状态带按宽度缩放，Boss 顶栏为小地图与雕花顶框留出空间。
- 战斗栏表现刷新以 30 FPS 为目标，覆盖时间、切人冷却、技能冷却、大招能量和小地图位置刷新。
- 战斗地图边界在世界空间以蓝色边框显示，玩家不能越过边界
- 无尽战斗顶部时间显示为 `N层 · 时间 mm:ss`；Boss 出现后 Boss 名同样带当前 N 层。
- 无尽战斗左上角在骨头/阮石状态下方显示 `速度 ×1 / ×2` 开关；开关只影响当前战斗，不写入存档，死亡、重开或离开战斗后恢复 `×1`。
- 高级信息可通过按键切换显示
- 开发者性能信息包含 FPS、帧时间 p95 / p99 / max、自动存档 SavePeak、运行时实体计数、新怪入场队列 SpawnQ、保存峰值规模、敌人/敌方弹幕/掉落物批处理状态与峰值计数，便于在高密度战斗或长时间游玩中对比优化效果；开启“记录性能日志”后会额外把周期样本和 `>=33.4ms` 慢帧样本写入 JSONL 日志。

## 营地与出击整备

- 无尽营地场景为 `res://scenes/endless_camp.tscn`，默认 `WASD` 移动、`F` 交互，提示读取当前改键。接近时高亮最近可用交互点；每个面板都停止移动、隐藏世界提示并阻止重复 `F`，`Esc` 先关闭面板、再返回主菜单。
- 概览常驻显示档案、骨头、最高解锁 N、下一局阵容、携带数量/上限与明细、最近通关收入或进行中战局。顶部直接提供携带物品、队伍整备、出击和主菜单入口。
- 场景采用仓库现有 Tiny Swords 草地、道路、建筑和植被；装备商人、物品商人、驻营角色、训练场、整备台和无尽传送门分区布置。
- 四名角色（含机械师）都有驻营实体。操作形象使用当前阵容第 1 位；同角色驻营实体隐藏，重排/换人后同步刷新。其他角色显示队员/候补身份，交互展示当前定位、基础属性、五个主动与大招，并可进入队伍整备。
- 阮狗直接打开携带物品商店，不再要求重复推进介绍台词；铁匠打开同一商店的装备分类。商店提供 5 种阮石和 12 种装备，按全部/阮石/装备/已携带筛选，左列选择、右侧查看当前与下一份累计效果。
- 每份物品固定 5 骨，购买即携带，允许重复购买；“购买 1 份”与“退还 1 份”分别操作。满额时购买禁用、退款仍可用。写盘失败显示原因并保留原骨头与物品；不存在单槽装备、无限升级或单独仓库。
- 整备台和顶部队伍入口复用 `scenes/UI/team_swap_panel.tscn`：左列当前 3 人，右列候补；支持替换、相邻前移/后移，选中角色显示定位与基础属性。1 号位为下一局首发，存档失败回滚。主线准备界面复用相同功能。
- 无尽传送门与顶部出击按钮打开选层器，并展示下一局阵容与携带确认。无进行中战局可选择 `N1...最高通关+1`；有战局时只允许继续原层、原战斗阵容。营地阵容调整用于下一局；携带物修改在继续时生效，界面明确说明此边界。
- 训练场是独立入口，确认后进入移动教学，取消留在营地。不会改变骨头与携带物品。
- 共用暗金弹窗与中文阅读字体，固定底部操作区；商品与详情独立滚动，键盘焦点保留并在关闭时返回入口。1280×720 与 960×540 的面板范围及操作按钮有回归检查。

## 角色面板 / 构筑档案

飞眼群「啄眼」触发目盲时，世界画面仅显示玩家周围半径 160 世界单位的圆形区域，范围外为不透明黑色；遮罩跟随玩家和镜头缩放，保留 HUD 与菜单交互。持续 1.5 秒，不叠加或刷新；每位玩家共享 10 秒触发冷却，暂停时停止计时。运行存档保存 `blindness.remaining` 和 `blindness.cooldown_remaining`，旧存档缺少该字段时默认无目盲。净化只清除目盲持续时间，不重置触发冷却。

触发方式：`C`。面板打开时暂停战斗，关闭后按当前奖励、暂停或游戏结束状态恢复暂停规则。

当前人物页采用「总览 / 技能 / 祝福 / 装备」四栏目与固定来源区：

- 默认打开总览并选中攻击力。左侧为队伍角色，中间为当前栏目，右侧为所选条目详情；点击或键盘聚焦选择条目，来源区保持位置。`Ctrl+Tab` / `Ctrl+Shift+Tab` 循环切换栏目，`Tab` / 方向键浏览，`Enter` 选择；关闭提示随人物页键位设置更新。
- 身份区显示像素角色、本局等级、定位与当前站场 / 候补。选择另一名角色只改变查看对象，不触发换人或登场；栏目和所选属性保留，角色独有条目缺失时回到首条。
- 总览按输出、生存、机动与循环排列 14 项：攻击力、普通攻速、基础攻击速度、增伤、暴击率、暴击伤害、当前/最大生命、护甲、减伤率、闪避率、状态抗性、生命回复、移动速度、通用冷却缩减。列表支持滚动，最低 960×540 窗口可访问全部属性。
- 右侧来源使用实际战斗 getter，并记录攻击、攻速、移速、生命、闪避、减伤的实际运算项。固定加值和倍率分开列示，祝福显示名称及阶级数量，道具与阮石注明持有数量。攻击力已含通用增伤，技能倍率、暴击和目标防御另算；不把来源合计再乘到攻击力上。
- 闪避与减伤按照剩余命中/伤害概率相乘合成。生命回复汇总道具、属性及神恩每秒折算，另行说明触发回复和阮石定时回复；通用冷却缩减汇总道具与奥术充能，单技能最终冷却见技能详情。
- 技能页分固有能力、主动技能、终结技；剑士、法师、机械师各 9 项，枪手保留独立猎杀共 10 项。三个角色普攻与剑刃风暴显示现行LV0～9构筑、已选择分支与下一级效果，不展示旧5/10级占位天赋；LV0普攻不标为未获得。其余技能维持现有成长显示。未获得主动技能说明通过「获得技能」卡解锁，终结技不显示虚构等级进度；移除旧祝福配方解锁/进化提示。
- 机械师八条成长线提供等级加成前后对照，人物页和 HUD 的参数读取战斗 getter；地雷/力场不再固定显示 1 级数值。炮台运行档新增 `progress_id` 区分登场与主动部署，旧档缺省按主动来源恢复。
- 已有 `level_talents` 在技能页末尾作为只读「已获得强化」清单展示。占位强化明确标记效果未实装；不恢复其停用的授予入口。机械师技能槽显示专属天赋名、完整效果和「已生效 / 待选择 / 5 级开放选择」；其他角色未实装槽仍显示占位状态。
- 祝福按全队共享与匹配技能生效分组，显示 I—IV 各阶数量；可合计的属性同时汇总主属性和附加属性（如焰阳 I×2 为固定攻击 +4），复杂条件效果逐阶展示。右侧明确每份效果，避免把最高阶单份效果当成总效果。祝福只读，不提供合成。
- 装备页先列全队共享阮石，再列当前角色普通道具，显示数量和实际合计效果；普通道具既可点击「赠与队友」，也可右键赠与其中一个。继续由原装备系统检查目标、持有数量和上限；阮石不可赠与。
- 长列表与详情分别滚动，空状态提供说明。打开、浏览与关闭不修改战斗角色和构筑状态；从奖励选卡打开再关闭仍保持暂停，从普通战斗关闭则恢复游戏。

Rect2(Vector2(-1600.0, -900.0), Vector2(3200.0, 1800.0))

- 红色：普通敌人 / Boss

## 性能日志

- 开关入口：主菜单设置或暂停菜单的“记录性能日志”。
- 默认关闭，建议只在复现卡顿前开启，复现几秒后关闭。
- 日志路径：`user://performance_trace_latest.jsonl`，每次重新开始记录会覆盖上一份。
- 每行是一个 JSON 对象；`reason=periodic` 是固定间隔样本，`reason=slow_frame` 是单帧耗时不低于 `33.4ms` 的慢帧样本。
- 样本包含：FPS、`delta_ms`、生存时间、当前 N 层、玩家等级、实体计数、待刷怪队列、批处理状态、帧时间分位数、当前帧/峰值 counters、SavePeak 和性能 feature flags。

## 存档结构

战斗数值存档使用当前防御模型：角色与敌人的护甲字段会随运行状态保存和恢复；低血装备使用 `equipment_low_health_damage_reduction_rate`，读取旧存档时兼容旧的 `_value` 字段。闪避与减伤字段按当前闪避率、减伤率语义解释。

核心脚本：
`scripts/save_manager.gd`

存档根目录：
`user://story_slots` 与 `user://endless_slots`

当前存档结构：

- `meta.json`
  记录最近使用的存档位等元信息

- `slot_x/story_profile.json`
  主线存档资料

- `slot_x/run_save.json`
  战斗中的继续存档

- `slot_x/run_save_backup.json`
  战斗存档备份

自动存档性能验证：

- 正常战斗会按 `scripts/main.gd` 的 `autosave_interval` 周期自动写入，当前默认约 2 秒一次。
- 升级、祝福绑定和技能奖励确认后的补充保存会延后到后续帧，与 HUD 完整刷新合并调度，避免奖励点击同一帧同时承担发牌、应用奖励、完整 HUD 文案重建和保存写入。
- 战斗存档固定覆盖当前存档位的 `run_save.json` 和 `run_save_backup.json`，不会按时间追加历史快照，因此磁盘文件数量不会随游玩时间增长。
- 战斗存档内容包括生存时间、BGM 播放位置、已刷精英/小 Boss/Boss 计数、玩家运行态，以及当前敌人、敌方弹幕、经验晶体、回复道具和未拾取骨头的运行态数组。
- 最终 Boss 收尾期间新发射的基础炮弹保存 `boss_finishing_shot`，恢复后仍不延长演出收尾；原演出弹丸及其分裂子弹继续正常参与完成判定。缺少该字段的旧档采用原等待规则，对象池复用会重置标记。
- 无尽运行档额外保存 `run_tier` 与 `run_id`；同层中途退出可继续，通关、死亡或主动结束后清除。
- 无尽档案 `endless_profile.json` 持久化 `bones`、允许重复 ID 的携带列表 `ruan_stone_purchased`、`highest_cleared_tier`、`selected_tier`、`last_rewarded_run_id` 和 `team_order`。`ruan_stone_levels` 在规范化时清空，`equipped_ruan_stone` 只保留兼容展示，不决定唯一生效物品。
- 故事档 `story_profile.json` 与无尽档案都保存 `team_order`（恰好 3 名不重复角色）；缺省或非法时归一化为默认队伍剑士、枪手、法师，旧档自动兼容。营地整备台与主线准备界面的换人面板替换或重排后检查写盘结果，成功才发布对应存档的 `team_order`，下一局战斗生效；失败回滚，继续中的阵容不改。
- 无尽档案增加 `last_clear_summary = {tier, bones, first_clear}`，和幂等奖励在同一次写入保存，用于返营回顾；缺省/非法时为空，不补发奖励。返营仅清理战斗运行档，永久携带列表与骨头保持不变。旧版本已清掉且没有历史记录的物品无法自动重建。

- 旧四难度档案迁移保留骨头与阮石，删除 `difficulty` 并从N1开始；缺少有效身份的旧run不提供续战，不在读档列表时删除。明确放弃时先复制 `.recovery_*` 原始诊断文件，再清运行档。
- 旧战斗存档仍可读取角色快照，但基础生命与基础减伤始终采用当前角色数据库数值，避免平衡更新被旧 `roles` 字段覆盖。
- 已停用的开局英雄特性选择不再写入 `opening_trait_choice_completed`；旧存档中的该字段会被直接忽略，不影响其余运行态读取。
- 活动技能天赋菜单不会重复增加普通 `pending_level_ups`。技能达到 5 级时进入待选，活动菜单保存规范化上下文（`skill_talent_offer=true`、`level_talent_offer=false`），继续游戏时按当前队伍与该技能等级重新生成二选一。
- 技能等级保存在 `role_special_states[role_id].skill_levels`，天赋位选择保存在 `role_special_states[role_id].skill_talent_slots`（含 5 级手动选择结果与 10 级自动补齐的另一个天赋位）。
- 机械师已保存的天赋位直接启用对应专属效果，不新增存档字段。双守卫、雷阵、两类机炮和重炮按保存的实例数组恢复，不重放施放；守卫次数、力场计时和炮台来源/剩余寿命保留，不回填。高爆参数在飞行物重用时清空，飞行物本身沿用既有不保存的边界。
- 玩家等级每 3 级的角色天赋入口已停用：`pending_level_talent_choices` 不再累积。已选角色天赋仍保存在 `role_special_states[role_id].level_talents`，互斥选择保存在 `level_talent_group_locks`，两条读取链保留待重新设计。旧 `skill_talents` 在规范化时清空。
- 运行存档以 `ability_runtime` 保存六个技能 ID：`blade_storm`、`crescent_wave`、`infinite_reload`、`shrapnel_field`、`meta_field`、`surging_wave`；读取时仍兼容旧扁平字段。
- 六个能力都保存本次施放的天赋快照。剑刃风暴、无限装填和梅塔领域恢复计数与活动实例状态；月牙剑气弹体与散弹场按已序列化状态重建。
- 限制：现有通用玩家 `Bullet` 实例和已排队但尚未执行的 scheduler 回调不跨存档。因此，读档会丢失仍在飞行的潮涌波，以及尚未执行的延迟回调；这不是已恢复的能力实例的一部分。
- 性能面板会显示 `SavePeak` 与保存峰值规模（敌人、敌方弹幕、经验晶体、回复道具、payload KB），用于排查“玩着玩着开始掉帧”的存档尖峰。
- 自动化验证仍可通过性能 feature flag `disable_autosave` 做无 UI 对照；例如设置环境变量 `MY_GAME_PERF_DISABLE_AUTOSAVE=1` 后运行游戏，可临时跳过周期性自动存档。默认不开启该开关，不改变正式玩法。

## 继续游戏规则

- 强退或中途返回主菜单后，允许继续当前战斗
- 继续目标通常回到 `main.tscn`
- 无尽选档统一进入营地；传送门负责选择新 N 层或继续当前层。
- 无尽最终Boss位于第20波；完成最终波祝福后结算固定/首通骨头、解锁N+1、清运行档返营。写盘失败保留结果并提供重试，不提前清档。
- 结算使用 `run_id` 幂等，开发者模式不读取、写入、清除或推进正式无尽进度。
- 无尽模式死亡或确认“结束本轮并返回营地”会清除战斗存档，但保留永久骨头与阮石
- 如果没有战斗存档但有主线存档，则回到主线准备流程

## 当前 BGM 规则（2026-10-25）

原创配乐位于 `assets/music/`，运行时入口仍为 `scripts/bgm_player.gd`；`scripts/audio/music_catalog.gd` 只负责身份与曲目选择。旧 `menu_bgm.mp3/.ogg` / `game_bgm.mp3/.ogg` 源文件保留，当前场景不再引用或播放；`export_presets.cfg` 明确排除这四个占位文件。包内容检查验证旧曲不可载入、全部14首原创Ogg可载入，不扩大到其他素材的许可核查。

| 场景 / 真实战况 | 曲目 |
| --- | --- |
| 主菜单、故事 / 无尽选档、主线准备与阅读、无尽营地、普通波收尾与整备 | `camp_signal` |
| 主线第一 / 二 / 三关 | `stage_frontpost` / `stage_rift` / `stage_core` |
| 无尽普通战斗波1—5、奖励波7/12/17 | `stage_frontpost` |
| 无尽普通战斗波8—15 | `stage_rift` |
| 无尽普通战斗波18—19 | `stage_core` |
| 精英冲锋骷髅 / 精英分裂骷髅实际登场 | `elite_ram` / `elite_splitshot` |
| 幽影树人 / 引渡人 / 地瑰灵实际登场 | `boss_tree` / `boss_rebirth` / `boss_rose` |
| 被污染的魔法石真实阶段1 / 2 / 3 | `boss_spellcore_1` / `_2` / `_3` |
| 本关 / 本局实际通关、实际失败 | `victory` / `defeat`（各只播放一次） |

- Boss身份优先于精英，精英优先于关卡曲。双精英共存时固定保留冲锋曲，冲锋精英实际死亡后才切分裂曲；不按第18秒预测第二只精英。引渡人墓碑复活期间保留同一Boss曲，不触发胜利。
- 无尽第6/11/16/20波的Boss由实际生成对象覆盖基础曲；第5/10/15/19波的精英同理。普通波收尾、选卡、整备使用营地曲；第20波实际击败后的收尾可播放胜利曲。逐波奖励不播放通关短曲。故事即时返营时，胜利短曲在准备场景完成一次后转回营地循环。
- 根节点子对象入树后，播放器只缓存有音乐身份的特殊敌人，兼容先入树再恢复存档属性；每0.25秒检查这些对象及现有波次 / 结果状态。没有逐帧遍历普通敌人，音乐不驱动攻击或伤害节奏。
- 菜单、选档、营地与准备场景之间沿用本次会话的营地曲播放位置，短入场淡化避免非零位置直接进入；父场景重复调用开始播放不会把主题重置为0。交接只存在内存，不写存档，进入战斗清除交接。
- 循环曲使用原生Ogg循环，无须依赖 `finished → play()` 重启。普通切曲约1.4秒等功率交叉淡化；魔法石同源阶段曲约0.8秒使用互补线性增益，并沿用当前播放位置；结果曲约0.45秒淡入。每个场景最多两个音乐播放实例，退出时一并停止释放。
- 沿用音乐音量与静音设置，同时作用于交叉淡化的两条声部；0%静音。暂停冻结两条声部和过渡，恢复沿用现有0.25秒延迟，后来的暂停 / 切曲 / 退出会取消旧续播请求。结果短曲允许在结算暂停时播放，播完保持结束状态。
- 沿用旧运行档的 `music_position`，根据恢复后的关卡、波次和特殊敌人重新推导曲目，不增加存档字段；超出新循环长度的位置取模，负数和非有限位置归零。无头模式仍执行选择逻辑，禁止两条声部实际播放。
- `scripts/tests/music_context_smoke.gd` 自动覆盖身份与20波映射、双精英、墓碑、阶段位置、重复事件、暂停 / 延迟取消、旧档位置、静音、音量、结果结束、返营转场和真实菜单→选档的营地续接；自动状态检查不能替代最终混音听感验收。

## 2026-10-25 会话与恢复边界

- 暂停菜单、奖励、人物页与结果各持有自己的暂停原因，关闭一个界面不会释放其他原因。嵌套设置沿原菜单关系关闭。
- HUD与配乐读取同一个只读会话视图，包含模式、阶段、结果、关卡、波次和目标计时。前两关仍显示生存剩余时间；第三关显示“讨伐用时”，超过300秒也不会暗示已经胜利。
- 敌人资料/旧档恢复完成后才发出配置完成通知，配乐不再靠延后一帧猜测敌人身份。曲目、音量、淡化与已保存播放位置沿用原合同。
- 运行档先验证直接消费的嵌套载荷，再创建对象；坏主档可回退好备份。运行态恢复失败时保持主备文件、阻止自动保存和继续战斗，并可安全返回菜单。
- 无尽结算已提交、但旧运行档清理失败时显示重试，重试只完成未完成步骤；选层清理失败不会发布新层状态。
- 四角色20主动技能共用实例对应表，机械师五技能的自动/手动切换真实生效。火球提示列出当前爆炸倍率、半径、灼烧时长与百分比，升级预览使用同一成长常量；未把所有其他技能改成完整实时数值表。

验收入口与具体保存兼容边界见[架构整改记录](implementation/2026-10-25_架构健全性整改.md)。

## 2026-10-23 保存恢复与反馈

- 永久档同时维护 `story_profile_backup.json` / `endless_profile_backup.json`，备份内容为上一次验证通过的状态。主档不兼容新版本时拒绝降级；主档损坏时可显式恢复有效备份，恢复前保存原始文件；主备都损坏时不按空槽覆盖。
- 运行档先校验玩家载荷、模式/槽位和尝试身份；语法合法但语义无效的主档也会回退备份。列表与读取不归档、不删除。
- 运行档新增 `reward_state`，保留小Boss候选及连续奖励上下文；主线用 `story_attempt` / `pending_settlement`，失败/放弃用 `pending_run_end`。恢复顺序优先完成已有结果，再恢复装备奖励与波末祝福。
- 成果已提交但run未清理时只重试清理，不重新发奖。失败和放弃保留永久进度，记录时间、等级、阵容、装备数与未分配点数；同关重试创建新尝试。

- 窗口关闭请求会先保存；写盘失败时保留当前场景并显示错误。返回主菜单与最终结算同样检查保存结果。

- 暂停页的“设置与按键”复用完整设置面板，改键期间Esc先取消捕获，设置关闭后仍保持战斗暂停。新增界面/结果音量、减少镜头/奖励卡/对话动画、出怪预警常亮、剧情正文放大；预警常亮不改变刷新时序与判定。
