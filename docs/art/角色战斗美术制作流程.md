# 角色战斗美术制作流程

本流程适用于新制或重制角色及 Boss 演出。先明确动作过程和真实事件，再确定人物母版与风格参考、生成逐帧源、整理导出、接入表现层，最后在实际游戏画面和正式包中验证；具体帧数、画幅与接口按角色和招式决定。

**2026-11-06 能力更新：**OpenAI 官方已提供 Image 2.6 GIF 生成功能。后续入口实际支持时，优先尝试以人物母版生成真实动画帧；当前会话一次内置 GIF 探针实际返回单帧 PNG，本机旧 CLI 也未适配。项目尚未实测人物 GIF 或其透明效果，不将 GIF 当作运行素材格式；[能力核查](../design-reviews/2026-11-06_ImageGen2.6动画生成能力核查.md)保留参数与接口证据。

## 动作契约与参考

1. 先读现有战斗规则与事件，写明谁出手、朝向和攻击范围，起势、蓄势、释放、接触和收势如何衔接；标记真实预警、释放、命中或延迟落点及其顺序。分清表现对象和可受击实体，列出本次保留的数值、碰撞、时机及存档边界。
2. 使用已经确认的人物母版确定脸、发型、服装、武器和识别物；另选动作／画风参考。身份、风格与动作参照分别记录，外部参考只在其授权范围内使用，不能直接当运行纹理或自动变成人物身份。贾苇索的母版和风格来源见[战斗素材](../../design/jia-combat-20261027/README.md)。
3. 先盘点已有特效和头像：合适时复用，缺失时单独制作。明确每段动作、镜头容纳的轮廓、关键接触姿态和目标帧数；帧数是本次计划，不是所有人物的统一规定。保留来源、参考用途、提示词、选版及弃用记录，核对第三方素材的实际使用边界，见[素材说明](../../THIRD_PARTY_NOTICES.md)。

## 生成及可复用请求

当前入口确实支持 GIF 生成与必要参数时，优先以人物母版分别生成待机、移动、攻击等真实 GIF；下载后核验返回文件本身确为多帧动画，再逐帧检查。若入口只返回 PNG，改用静态多姿态表作为源图，按实际轮廓选帧；不得将后期拼出的 GIF 记作模型直出。文件透明性、连续性和身份一致性都须实际验收，不能由提示词或静态透明能力推断。

每次生成请求可按以下内容填写；保持每段动作单独可审，不把示例帧数或尺寸当成强制值：

```text
对象与身份：[人物／阶段；母版及其用途；脸、发型、服装、武器和不可改变的识别物]
动作：[单一动作；起势→蓄势→出手／接触→余势或复位；方向与身体重心]
参考：[画风参考、动作参考及各自用途；不把外部作品人物复制成角色]
输出：[入口支持时请求真实 GIF；填写帧数和每帧时长，先用 n=1、size=auto 验证；循环仅在适用时要求]
构图：[完整人物与武器留在画幅内；标明脚底锚点、主体比例与运动范围]
透明：[先核实 GIF 实际透明效果，不直接组合 transparent 与 GIF；若不透明，仅作动作参考或另取透明源]
约束：[不加文字、水印或背景装饰；人物与装备逐帧一致；接触姿态清楚]
```

使用支持 GIF 的入口前，核对其模型、输出格式、帧数／时长控制及 GIF 预览访问条件，保留实际请求参数和原始返回。Image 2.6 的官方指南目前给出 2—16 帧、每帧 20—2000 毫秒，先以 `n=1`、`size=auto` 核查；请求时帧数、帧尺寸和生成数量共同受模型像素预算约束。静态母版参考使用图像编辑入口。GIF 不直接请求 `transparent`：官方透明背景参数的说明要求 PNG／WebP，GIF 透明输出尚未验证。不透明 GIF 只能作为动作参考，或另取透明源后整理为运行 PNG。官方支持不等于当前工具或账号已具备相同入口，具体范围见[能力核查](../design-reviews/2026-11-06_ImageGen2.6动画生成能力核查.md)。

以下是**仅供实际支持这些字段的 [Image API 编辑入口](https://developers.openai.com/api/reference/resources/images/methods/edit)**使用的 `POST /v1/images/edits` JSON 请求体。先将占位内容替换为已上传、已确认母版的 `file_id` 和上面的动作请求；也可将该对象改为 `image_url`，使用完整 HTTPS 地址或 base64 data URL。模型可以换成 `gpt-image-2.6-flare`。不能把这些字段当作当前内置工具或旧 CLI 已支持的参数：

```json
{
  "model": "gpt-image-2.6-sunburst",
  "images": [{"file_id": "<已上传母版的file_id>"}],
  "prompt": "<替换为上面的单段动作请求>",
  "output_format": "gif",
  "frame_count": 8,
  "frame_duration_ms": 100,
  "size": "auto",
  "n": 1
}
```

示例不设置透明背景或遮罩，帧数和时长按招式需要调整；不能把官方的 16 帧上限当作项目必须保留 16 帧。导出前还应核对目标设备的纹理尺寸、同时加载角色数和内存占用，按实际画质与预算取舍。

拿到原始文件后，可以把下例路径替换为实际返回文件，做只读检查；确认 GIF 格式、实际多帧、每帧时长及透明像素，再在深浅背景上检查循环接缝、人物与武器漂移、裁切、滑步和透明边缘。不同帧的内容仍需人工观察，文件格式与帧数不证明动作正确。单帧 PNG、静态 GIF 或事后合成预览不能算真实逐帧生成；若结果不可用，保留原证据并采用 PNG 姿态表路径。

```bash
python3 - /替换为实际返回文件路径 <<'PY'
from hashlib import sha256
from pathlib import Path
from PIL import Image, ImageSequence
import sys

path = Path(sys.argv[1])
raw = path.read_bytes()
with Image.open(path) as image:
    print('format:', image.format, 'size:', image.size,
          'frames:', getattr(image, 'n_frames', 1),
          'animated:', getattr(image, 'is_animated', False),
          'loop:', image.info.get('loop'))
    for index, frame in enumerate(ImageSequence.Iterator(image)):
        alpha = frame.convert('RGBA').getchannel('A').getextrema()
        print(index, 'duration_ms:', frame.info.get('duration'),
              'disposal:', getattr(frame, 'disposal_method', None), 'alpha:', alpha)
print('header:', raw[:12].hex(), 'sha256:', sha256(raw).hexdigest())
PY
```

## 切帧、尺度与导出

- 将 GIF 按 disposal 逐帧解码成完整画面，保留每帧 duration、disposal 和循环信息，再用 Aseprite 检查、整理；不能把差分矩形直接当作完整人物帧。保留未改的生成原件。PNG 姿态表的行列和间距可能不规则，应先看每个动作，再以 Aseprite Lua 脚本按透明区域提取，不能按假定网格盲切。两种来源都需量测髋部与脚底锚点、核查武器和裁切越界；换源后重新选帧与量测。
- 最终人物帧导出为真正透明的 RGBA PNG，不把纸底、场景或卡片稀有度色烘入人物；立绘与卡片的人物、背景、边框和文字保持分层。GIF 的透明能力须单独检查，不因要求透明就假定生成结果合格。
- 同一来源按固定尺度换算并统一锚点，不因奔跑或攻击俯身而逐帧强拉到相同高度。用可见身体而非透明画布或武器定人物比例；现阶段贾苇索站姿身体高 72 世界单位、脚底对齐 0。其他人物结合战场比例和自身形象核对，不要求每种姿势都达到站姿高度。
- 人物帧共用不超过 64 色的调色板，运行像素帧使用二值 alpha（0 或 255）与最近邻缩放；头像独立整理并导出。保留运行 PNG、可编辑 `.aseprite`、原始生成 GIF 或 PNG、提示词与素材清单，记录尺寸、来源、版本和 SHA-256。原画由 ImageGen 生成；Pillow 等程序仅用于只读核验，不代替绘制。
- 每次新增或替换战斗角色／敌人的帧图、调整帧区域或清单后，在仓库根目录执行 `python3 scripts/tools/build_battle_sprite_bounds.py`，更新 `assets/data/chronicle/battle_sprite_bounds.json` 中的透明边界、尺寸与源文件哈希。新增当前生成器未枚举的素材路径时，先补齐其输入枚举；`python3 scripts/tools/build_battle_sprite_bounds.py --check` 会检查数据是否过期，并由 `scripts/check_project.sh` 调用。该元数据只用于画面布局，不能改变碰撞和技能范围。

贾苇索是具体范例：刀和枪各待机 4、奔跑 8、攻击 4 帧，共 32 个人物帧；斩击、突刺、横扫各 4 帧，共 12 帧特效。人物帧为 192×192、锚点 `(96, 176)`，站姿可见身体 80 像素，乘 0.9 得 72 世界单位。独立生成的头像在 Aseprite 中按 64 像素原生尺寸整理后最近邻导出 128 像素。以上帧数和画布是此角色方案，并非所有角色的强制规格。

## 游戏接入

特效先检查当前仓库中可用的帧和贴图，确认来源、风格、方向与实际命中范围后再复用。优先提取 `SpriteFrames` 或 PNG，接到当前战斗的纯表现层；伤害、资源和命中仍由新战斗内核负责。不要把旧弹幕、碰撞或技能业务逻辑随场景一起搬回。艾玛、田秀和马三娘的素材对应与验收例子见[本轮记录](../implementation/2026-10-28_田秀马三娘与战斗特效复用.md)。

表现层适配角色已有玩法，例如贾苇索提供 `set_moving`、`set_weapon`、`play_attack`，以实际施放事件驱动攻击。成功施放才触发，缺魔、冷却或缺目标的失败不播攻击；用施放序号去重，切回角色时不重播旧动作。手动技能优先普攻；若伤害即时结算，攻击从接触帧开始呈现。攻击不阻止移动，不因换图改技能数值。

对有预警、延迟命中或多次落点的招式，分别以真实预警、释放、命中事件推进对应阶段，按本次素材清单标记接触帧；GIF 源帧时长只作制作信息，不把整份 GIF 按自身时长／循环直接放进战斗，不自动改变战斗的预警、接触和收势时刻，也不能依靠一段等速动画自行制造伤害或提前播放接触效果。张辽召唤案例中，高顺效果的接触索引 4 对应真实释放，陈宫效果的接触索引 5 对应实际落阵；陈宫独立视觉站位不改变模拟位置，危险预警始终保持可读。其 60 个人物帧、16 个特效帧、镜头与性能边界见[演出记录](../implementation/2026-11-06_张辽双协同召唤演出升级.md)，不作为其他角色的帧数或画幅规格。

按真实朝向显示动作与特效，检查特效范围和命中范围；人物动画遵从战斗暂停状态，特效按战斗时间推进，战斗结束按现有生命周期清理。贾苇索目前复用八向移动输入与左右镜像，并非八方向独立绘制的动作集。

## 复现与只读核验

在仓库根目录安装 Aseprite、Godot 4.6.2、Python Pillow 和 FFmpeg。下例的 `aseprite`、`godot` 从 PATH 查找；未加入 PATH 时，将命令替换为本机安装的 Aseprite 可执行文件路径。重新导出会覆盖贾苇索运行素材；换源图须先改选帧和锚点并检查结果。

```bash
aseprite --batch --script scripts/tools/import_jia_art.lua
godot --headless --path . --editor --import --quit
godot --headless --path . --quit
XDG_DATA_HOME=/tmp/mygame-jia-art godot --headless --path . --script scripts/tests/jia_combat_art_smoke.gd
XDG_DATA_HOME=/tmp/mygame-jia-scale godot --headless --path . --script scripts/tests/chronicle_battle_scale_smoke.gd
XDG_DATA_HOME=/tmp/mygame-jia-combat godot --headless --path . --script scripts/tests/chronicle_combat_smoke.gd
XDG_DATA_HOME=/tmp/mygame-jia-ui godot --headless --path . --script scripts/tests/chronicle_playable_ui_smoke.gd
```

以下仅仅读取贾苇索运行 PNG：检查尺寸、二值 alpha、人物帧共同色数，并将尺寸和哈希与素材清单比对。素材有意变更时，先复核后更新清单；用途和文件列表换到其他角色时相应调整。原始 RGBA 画稿允许半透明边缘，不套用运行像素帧的二值规则。

```bash
python3 - <<'PY'
from hashlib import sha256
from pathlib import Path
import json
from PIL import Image

root = Path('assets/players/jia')
manifest = json.loads(Path('design/jia-combat-20261027/manifest.json').read_text())
expected = {Path(item['path']): item for item in manifest['outputs']}
files = sorted(root.glob('*.png'))
assert len(files) == 10 and set(files) == set(expected)
actor_colors = set()
for path in files:
    image = Image.open(path)
    assert image.mode == 'RGBA', path
    alphas = set(image.getchannel('A').getdata())
    assert alphas == {0, 255}, (path, alphas)
    if path.name.startswith(('dao-', 'spear-')):
        frames = 8 if path.name.endswith('-run.png') else 4
        assert image.size == (192 * frames, 192), path
        actor_colors.update(pixel[:3] for pixel in image.getdata() if pixel[3])
    elif path.name.startswith('vfx-'):
        assert image.size == (512, 128), path
    else:
        assert image.size == (128, 128), path
    digest = sha256(path.read_bytes()).hexdigest()
    assert list(image.size) == expected[path]['size'], path
    assert digest == expected[path]['sha256'], path
    print(path, image.size, digest)
assert len(actor_colors) <= 64
print('人物不透明色数:', len(actor_colors))
PY
```

Godot 实际纹理预览在有图形显示的环境生成，随后可用 FFmpeg 整理为 GIF：

```bash
godot --rendering-method gl_compatibility --path . --script scripts/tests/jia_art_preview.gd -- --capture
ffmpeg -y -framerate 12 -i design/jia-combat-20261027/preview-frames/%03d.png -filter_complex '[0:v]split[a][b];[a]palettegen=stats_mode=diff[p];[b][p]paletteuse=dither=none' design/jia-combat-20261027/preview.gif
```

命令会写入 `preview.png`、`preview-frames/` 和 `preview.gif`。保留的[当前预览图](../../design/jia-combat-20261027/preview.png)与[动作预览](../../design/jia-combat-20261027/preview.gif)可作范例。

## 验收与留档

- 在 960×540、1280×720 和 1920×1080 查看实际 Godot 渲染与完整动作，核对身体、脚底、头像、武器、特效和战场比例；检查近边、近身、镜头取景、人物遮挡、敌方预警和受击点，而不只看静帧。减闪、低动态与暂停后仍应能辨认危险和实际接触。
- 回归成功施放、缺魔、冷却、缺目标、手动／普攻同时发生、切人及切回、暂停／恢复和结束清理；核对预警、释放、延迟命中与动作对应，队伍、装备、伤害和正常关卡流程不因美术替换改变。需要独立包时，在源码外验证运行资源、清单与导出可用。
- 记录前后同输入密集场景的事件、状态与性能；比较时检查设备和并行负载是否可比，保留慢帧及失败结果，避免用单次较好样本证明所有设备流畅。张辽案例的高负载对照和限制见其[实施记录](../implementation/2026-11-06_张辽双协同召唤演出升级.md)。
- 保存原始 GIF 或 PNG、提示词、可编辑文件、导出脚本及清单，记录来源、模型和接口是否实际可知、尺寸、alpha、色数与哈希；留下测试命令、日志、各尺寸截图及预览视频。实际 Godot 捕帧经 FFmpeg 合成的预览应标注来源，不能记为模型直出。贾苇索的结果见[实施与验证](../implementation/2026-10-27_贾苇索战斗美术接入.md)。

自动测试通过和截图复查只证明所覆盖的程序与画面检查；人物造型、动作观感与实战平衡仍需用户或相应负责人审看确认。
