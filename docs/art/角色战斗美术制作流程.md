# 角色战斗美术制作流程

本流程适用于新制或重制角色。先确认角色形象，再制作动作、特效和头像，最后以实际游戏画面检查；帧数、武器与表现接口按角色需求决定。完整范例见[贾苇索战斗素材](../../design/jia-combat-20261027/README.md)，更早的制作过程见[机械师重做记录](../../design/mechanic-rework-20261013/README.md)。

## 准备与生成

1. 与用户确认人物母版，确定脸、发型、服装、轮廓及识别物；另选风格参考来说明像素画法和动作呈现。风格参考不替代人物母版，也不自动决定新角色身份。贾苇索采用[已确认的起家立绘](../../design/jia-weisuo-20261027/jia-standing-v1.png)确定身份，以机械师动作图参考像素风格和流程。
2. 用内置 ImageGen 基于母版生成待机、奔跑、攻击等人物动作，将武器／技能特效分开生成，并独立绘制适合小尺寸阅读的头像。核查肢体、武器方向、画幅完整性与人物一致性；保留原始透明源图、每版提示词、参考关系、选用与弃用记录。必要时重新生成，不把每张源图都视为可直接切帧的成品。
3. 新制或重制人物素材使用真正透明的 RGBA PNG，纸底、场景和卡片稀有度色不烘入人物。立绘直接作为独立人物层叠到场景；卡片背景、人物、框与文字分层。核对素材来源和可公开范围，区分临时参考图与可发布源图；第三方分发条件见[素材说明](../../THIRD_PARTY_NOTICES.md)。

## 切帧、尺度与导出

- 生成图的行列和间距可能不规则，先看每个动作，再用 Aseprite 的 Lua 脚本按透明区域做连通区域提取。人工量测髋部与地面锚点并核查武器；源图改变时重新选帧和量测，不按假定网格盲切。脚本应检查选帧位置和裁切越界。
- 同一来源按固定尺度换算并统一锚点，不因奔跑或攻击俯身而逐帧强拉到相同高度。用可见身体而非透明画布或武器定人物比例；现阶段贾苇索站姿身体高 72 世界单位、脚底对齐 0。其他人物结合战场比例和自身形象核对，不要求每种姿势都达到站姿高度。
- 人物帧共用不超过 64 色的调色板，运行像素帧使用二值 alpha（0 或 255）与最近邻缩放；头像独立整理并导出。保留运行 PNG、可编辑 `.aseprite`、原始生成 PNG、提示词与素材清单，记录尺寸、来源、版本和 SHA-256。原画由 ImageGen 生成；Pillow 等程序仅用于只读核验，不代替绘制。

贾苇索是具体范例：刀和枪各待机 4、奔跑 8、攻击 4 帧，共 32 个人物帧；斩击、突刺、横扫各 4 帧，共 12 帧特效。人物帧为 192×192、锚点 `(96, 176)`，站姿可见身体 80 像素，乘 0.9 得 72 世界单位。独立生成的头像在 Aseprite 中按 64 像素原生尺寸整理后最近邻导出 128 像素。以上帧数和画布是此角色方案，并非所有角色的强制规格。

## 游戏接入

表现层适配角色已有玩法，例如贾苇索提供 `set_moving`、`set_weapon`、`play_attack`，以实际施放事件驱动攻击。成功施放才触发，缺魔、冷却或缺目标的失败不播攻击；用施放序号去重，切回角色时不重播旧动作。手动技能优先普攻；若伤害即时结算，攻击从接触帧开始呈现。攻击不阻止移动，不因换图改技能数值。

按真实朝向显示动作与特效，检查特效范围和命中范围；人物动画遵从战斗暂停状态，特效按战斗时间推进，战斗结束按现有生命周期清理。贾苇索目前复用八向移动输入与左右镜像，并非八方向独立绘制的动作集。

## 复现与只读核验

在仓库根目录安装 Aseprite、Godot 4.6.2、Python Pillow 和 FFmpeg。下例的 `aseprite`、`godot` 从 PATH 查找；本机如未将 Aseprite 加入 PATH，可把它替换为 `/home/weathour/programs/aseprite-src/build/bin/aseprite`。重新导出会覆盖贾苇索运行素材；换源图须先改选帧和锚点并检查结果。

```bash
aseprite --batch --script scripts/tools/import_jia_art.lua
godot --headless --path . --editor --import --quit
godot --headless --path . --quit
XDG_DATA_HOME=/tmp/mygame-jia-art godot --headless --path . --script scripts/tests/jia_combat_art_smoke.gd
XDG_DATA_HOME=/tmp/mygame-jia-scale godot --headless --path . --script scripts/tests/chronicle_battle_scale_smoke.gd
XDG_DATA_HOME=/tmp/mygame-jia-combat godot --headless --path . --script scripts/tests/chronicle_combat_smoke.gd
XDG_DATA_HOME=/tmp/mygame-jia-ui godot --headless --path . --script scripts/tests/chronicle_playable_ui_smoke.gd
```

以下仅仅读取贾苇索运行 PNG：检查尺寸、二值 alpha、人物帧共同色数，并将尺寸和哈希与素材清单比对。素材有意变更时，先复核后更新清单；用途和文件列表换到其他角色时相应调整。原始 RGBA 画稿允许半透明边缘，不套用运行像素帧的二值规则。

```bash
python3 - <<'PY'
from hashlib import sha256
from pathlib import Path
import json
from PIL import Image

root = Path('assets/players/jia')
manifest = json.loads(Path('design/jia-combat-20261027/manifest.json').read_text())
expected = {Path(item['path']): item for item in manifest['outputs']}
files = sorted(root.glob('*.png'))
assert len(files) == 10 and set(files) == set(expected)
actor_colors = set()
for path in files:
    image = Image.open(path)
    assert image.mode == 'RGBA', path
    alphas = set(image.getchannel('A').getdata())
    assert alphas == {0, 255}, (path, alphas)
    if path.name.startswith(('dao-', 'spear-')):
        frames = 8 if path.name.endswith('-run.png') else 4
        assert image.size == (192 * frames, 192), path
        actor_colors.update(pixel[:3] for pixel in image.getdata() if pixel[3])
    elif path.name.startswith('vfx-'):
        assert image.size == (512, 128), path
    else:
        assert image.size == (128, 128), path
    digest = sha256(path.read_bytes()).hexdigest()
    assert list(image.size) == expected[path]['size'], path
    assert digest == expected[path]['sha256'], path
    print(path, image.size, digest)
assert len(actor_colors) <= 64
print('人物不透明色数:', len(actor_colors))
PY
```

Godot 实际纹理预览在有图形显示的环境生成，随后可用 FFmpeg 整理为 GIF：

```bash
godot --rendering-method gl_compatibility --path . --script scripts/tests/jia_art_preview.gd -- --capture
ffmpeg -y -framerate 12 -i design/jia-combat-20261027/preview-frames/%03d.png -filter_complex '[0:v]split[a][b];[a]palettegen=stats_mode=diff[p];[b][p]paletteuse=dither=none' design/jia-combat-20261027/preview.gif
```

命令会写入 `preview.png`、`preview-frames/` 和 `preview.gif`。保留的[当前预览图](../../design/jia-combat-20261027/preview.png)与[动作预览](../../design/jia-combat-20261027/preview.gif)可作范例。

## 验收与留档

- 在 960×540、1280×720 和 1920×1080 查看实际 Godot 渲染，核对身体、脚底、头像、武器、特效与战场画面的比例；观察完整待机、移动、攻击及方向切换，而不只看静帧。
- 回归成功施放、缺魔、冷却、缺目标、手动／普攻同时发生、切人及切回、暂停／恢复、结束清理，检查攻击动作与实际命中时间、范围一致。检查队伍、装备和正常关卡流程没有因美术替换改变。
- 保存源图与提示词、可编辑文件、导出脚本及版本清单，记录 PNG 尺寸、alpha、色数与哈希；留下测试命令、日志、各尺寸截图和预览 GIF。贾苇索的结果见[实施与验证](../implementation/2026-10-27_贾苇索战斗美术接入.md)。

自动测试通过和截图复查只证明所覆盖的程序与画面检查；人物造型、动作观感与实战平衡仍需用户或相应负责人审看确认。
