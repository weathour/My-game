# 重构前运行基线

记录日期：2026-10-26；运行代码基线为 `fda3133`。本轮只更新和清理文档，没有实施新玩法。本页供后续定位差距，**不是继续完善旧玩法的任务清单**。目标规则见[当前设计共识](../00_当前设计共识.md)。

## 当前代码与新目标的差别

| 领域 | 重构前代码 | 新目标 |
| --- | --- | --- |
| 人物与队伍 | 剑士、枪手、法师、机械师四人角色库，选择三人轮换。 | 固定主角加至多两辅助，随行无人数上限，关间从全部符合战役条件的人物中换人；辅助可后台帮助或直接操作。 |
| 成长 | 各队员独立技能点；已有技能加点、空槽候选解锁；普通技能5/10级天赋槽和部分LV0～9专属分支并存。 | 人物卡和战斗经验提升人物等级，技能随等级自动解锁。 |
| 遗留数据 | 旧四选二、每3级角色天赋、108节点和属性卡等定义或兼容链仍有残留；不等于正常入口开放。 | 不作为新成长依据；是否删除代码及旧档处理在实施时决定。 |
| 关卡 | 无尽采用20波与N层；故事沿现有三关推进。 | 每小关四角场域；定时/击杀量提前出Boss，击败才过关，限时给额外经验。 |
| 永久收益 | 无尽骨头、阮石购买与携带、最高N；角色装备主要随战局保存。 | 人物及等级、持有加成和固定槽装备随主线推进。 |
| 主线 | 固定三关任务、对话、交付与练习重访；新关的局内成长边界沿旧实现。 | 战役与路线，成功关卡不能返回，状态跨小关延续。 |
| 失败 | 旧会话和模式各自结算/清理。 | 主角死亡才失败，回退本小关进关前快照；辅助阵亡后胜利仍保持不可用直至恢复。 |

现有程序并未具备新人物卡循环、主角与辅助的死亡语义、四角互斥场域或新主线保存合同。README曾保留更早的四选二描述，本轮已删除该过时说明；当前代码的旧成长以独立技能点入口为准。

## 可评估复用的工程基础

- Godot 4.6.2，主场景 `res://scenes/main_menu.tscn`；战斗入口 `scenes/main.tscn`。
- 战斗flow、角色与ability模块、统一伤害出口、敌人数据资源、弹体与空间查询。
- 场景内暂停原因集合与只读会话视图；HUD和配乐读取同一战斗状态。
- 原子主备写盘、坏档恢复、运行载荷验证、提交后更新界面、奖励身份防重。
- 敌人对象池退出释放、延迟命中核对激活代数、出生预警与真实命中范围。
- 原创界面框、角色与敌人素材、14首原创配乐、音乐鉴赏、设置/重绑/焦点和故事阅读组件。

这些基础可以复用，也需要按新规则调整。特别是旧永久拾取到账、波末奖励队列和故事重访不能直接用来实现新回退边界。

## 当前实际风险

- 小Boss奖励菜单退出后续战，停在默认暂停页再退出，会覆盖原先待恢复的奖励候选；已复现，尚未修复。涉及 `run_save_flow.gd` 与 `reward_flow.gd`。
- 2026-10-25高密度真实场景测量仍超过60FPS预算；较快的存档验证不能证明整局达标。
- Graphify缺失GDScript提取能力，现存图已过期；源码和当前状态入口优先。
- 原有运行档是否迁移至新体系尚未决定。文档删除不修改用户存档。
