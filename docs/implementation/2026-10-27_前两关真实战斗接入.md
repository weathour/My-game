# 前两关真实战斗接入

状态：已实现首个可玩段落，2026-10-27。依据[设计共识](../00_当前设计共识.md)和[架构提案](../design-reviews/2026-10-27_真实战斗架构与参考实现.md)。本轮由主 agent 完成，没有新开 subagent。

## 实际可玩范围

默认入口仍为 `scenes/chronicle/chronicle_shell.tscn`。标题选择“启程白门楼”，经过 S01 后进入 B01 城外异乡人；必须实际击败首领，才能进入 S02 艾玛加入和正常五选二。关间可配置辅助、换装备，随后进入 B02 入城旧街；战后选卡、重复升级、保存、鬼市事件均接通。B04 等后续战斗明确标为制作中，不能用演练胜利越过。

已实装八个人物：贾苇索、艾玛、乡勇刀手、乡勇枪手、猎户弓手、游方符师、行脚郎中、随军伙夫。其他人物保留目录预览，并标明尚未实装；本轮不会将他们的文案自动映射成通用能力或提前加入正式池。

本记录初次验收时使用基础竞技场、图集绘制与临时人形。同日用户纠正后已接回现有地图、人物／怪物动画、头像、特效与原HUD组件，删除临时人形；表现现状及新证据见[战斗表现与HUD复用](2026-10-27_战斗表现与HUD复用.md)。下方combat目录证据记录初次接入，后续截图在combat-reuse。

## 运行分工

| 文件／目录 | 实际职责 |
| --- | --- |
| `scripts/content/combat_catalog.gd` | 八人物、能力 Resource、七项属性、成长、持有加成、六装备、两关参数。定义按约定只读，集合亦设只读。 |
| `scripts/battle/character_runtime.gd` | 各人物独立 HP、MP、等级、经验、按技能 ID 保存的冷却；临时护盾、受击保护和加速。 |
| `ability_system.gd`、`ability_definition.gd` | 普攻、自动常规技能、手动技能与支援的统一激活检查；每次施放保存来源与参数。 |
| `targeting.gd`、`combat_resolver.gd` | 自动目标保持、范围形状与命中；统一伤害、防御、护盾、减速和死亡。核心不引用具体角色天赋。 |
| `enemy_runtime.gd`、`enemy_system.gd` | 近战、远程、精英与 Boss 的独立实体、前摇、攻击及移动。Boss 交替冲锋与扇形射击，半血后加快。 |
| `stage_director.gd` | 时间／击杀触发 Boss、停止普通刷怪、四角互斥选择和精英成果。 |
| `battle_session.gd` | 本关工作副本、固定逻辑拍、队伍切换、投射物、经验拾取与一次性结果。无文件写入或 UI 引用。 |
| `scripts/campaign/campaign_service.gd` | 编队、行装、主线节点、开池、剧情加入、战果提交、奖励领取与恢复语义。 |
| `campaign_store.gd`、`reward_rules.gd` | 临时文件原子替换、有效上一代备份；独立随机流抽取候选。 |
| `scripts/ui/chronicle/battle_view.gd`、`battle_canvas.gd`、`battle_art.gd`、`battle_hud.gd` | 实战 HUD、键盘输入交接与场景表现；不拥有成长和伤害规则。 |

旧 `chronicle_session.gd`／`chronicle_battle.gd` 只供完整界面回归夹具使用，默认产品入口不再使用它们。旧 `main.gd`／`player.gd` 链仍由标题的旧版战斗入口进入，未改造、未恢复历史归档实现，也不与新战斗互相调用。

首版敌人数上限为42／54，采用有界遍历和独立 RefCounted 实体，暂不使用对象池；每次创建给出本关唯一 ID，因此没有复用另一代实体的问题。后续提升密度时再引入空间索引和带激活代数的对象池。旧版的渲染帧伤害预算、全局缓存和天赋耦合没有带入新核心。

## 已落实规则

- 移动 WASD／方向键，Q／E 在存活成员中轮换，J／K 调用当前人物关键技能，Esc 暂停。新 `battle_*` 输入动作与旧版设置分开；当前尚无新键位编辑页。
- 切换公共冷却0.5秒，不给无敌、不刷新技能。仅前台直接承伤；辅助死亡强制退回主角，主角死亡失败。短暂受击保护属于实际受击人物，不属于切换收益。
- 普攻、自动技能与后台支援不耗魔法，手动技能消耗当前人物魔法。艾玛 Lv.2 自动解锁冰星，主角与艾玛 Lv.3 解锁第二个手动技能；N卡一个关键技能。技能和参数均为可调整的初版内容。
- 已配置人物推进自己的魔法与冷却；候补不参加计时。阵亡者冷却继续推进，但不回魔、不释放支援；这一时序作为当前实现默认值记录。
- 持有加成由已获得人物与等级计算，包括阵亡人物；本关经验升级引起的属性变化只存在于本次尝试。特殊功能不会通过仅持有卡片获得。
- 战斗经验按实际进关人数均分，阵亡者保留份额。内部使用六分之一经验点的整数单位，避免反复均分累积浮点误差；加载时规范化 JSON 数值。存活人物升级回满 HP／MP，阵亡人物不复活；重复卡升一级并保留经验。
- 刀与枪改变主角普攻形状，辅助保留自身形状；布甲受击加速，铁甲加防御并在受击时生成短护盾；余烬符、寒泉玉只对发出时的前台直接攻击附魔。切人不会改写在途弹体来源。
- 四角补给恢复当前人物资源，修习给当前人物24经验；两种挑战分别召唤选卡精英与装备精英，选一处即关闭另外三处。精英必须实际击杀。
- B01 Boss在65秒或28击杀时出现，B02在80秒或38击杀时出现；出现后停止普通刷怪。限时105／120秒内胜利额外获得18经验。数值是首版调试起点。
- Boss死亡在当前命中批次结束时终结战斗，未死精英不补奖；同批次主角与Boss死亡按失败。胜利收取剩余经验物，不给存活敌人补经验。暂停不推进逻辑时间。
- 普通五选二、抽卡精英五选三已走真实流程；章末七选三／七选四和至少两张重要卡由独立奖励规则验证，章末战斗与足量重要人物尚未开放。候选在已解锁池内去重，不足时拒绝生成，不偷偷引入锁定人物。
- 泉水事件已支持全收藏人物恢复和复活，不刷新技能冷却；前两关路线暂无泉水，可达的后续泉水节点尚随关卡制作开放。该规则有独立测试。

当前技能即时施放，不含完整蓄力／取消状态机、输入缓冲、召唤物、持续伤害、驱散、复活或代伤技能。这些扩展仍需对应具体角色；没有用通用空壳宣称实现。

## 保存与失败

正式存档路径为 `user://chronicle_campaign_v1/`，`schema=1`、`scope=campaign`；自动档和三个手动槽分别保存。旧版档案及 `chronicle_ui_v1` 演练档不迁移、不覆盖。

进关创建独立尝试 ID 与工作副本。未胜利离开或失败恢复进关前记录；胜利只接受当前尝试结果。存盘失败时保留重试权限，HUD提供重新提交战果，不能重复获得收益。辅助阵亡会跨关保存并从下一关编队移除。

每次新行军生成奖励随机种子，卡池与战斗随机流分离。首版两关的刷怪种子固定，失败重打沿用；奖励候选一旦生成便随选择一起保存。读旧档整体回退，并沿该档的奖励随机流继续。这是当前实现策略，后续可以调整未生成奖励的重抽规则。

JSON 使用完整浮点精度，加载时规范化领域整数和经验单位。写入先生成并检查临时文件，只备份经过校验的旧档，再原子替换；主文件损坏时读取上一代有效备份。正式档拒绝旧作用域、非法人物资源和不完整候选。

## 验证与证据

- [规则及保存日志](../design-reviews/evidence/2026-10-27/combat/rules.log)：`CHRONICLE_COMBAT_SMOKE PASS checks=66 failures=0`。包含真实攻击完成两关，以及失败回退、个人资源、后台权限、技能自动解锁、经验均分、同批次胜负、装备范围、泉水、阵亡重复卡、结果幂等、选择续存和备份恢复。
- 日志中的两个 `/proc/chronicle-combat-*-read-only` 目录错误是故意注入的写盘失败，用于验证战果重试与选卡回滚；不能把它们混同于未知运行错误。
- [实战 UI 无图形检查](../design-reviews/evidence/2026-10-27/combat/ui-headless.log)与[真实渲染检查](../design-reviews/evidence/2026-10-27/combat/ui-rendered.log)：从标题经剧情、真实胜利、选卡、配置艾玛与郎中、换长枪、第二关、五选三直到后续关卡锁定。键盘覆盖移动、暂停、切换与耗魔。模拟驾驶通过输入意图和实际攻击推进，不调用演练胜利按钮。
- 真实渲染用独立 SubViewport 避免宿主窗口管理器的 DPI／缩放竞态，逐张记录并核对像素尺寸。截图12张，包含1280×720、960×540、1920×1080。[首战](../design-reviews/evidence/2026-10-27/combat/screens/03-first-battle.png)、[小窗口](../design-reviews/evidence/2026-10-27/combat/screens/08-compact.png)、[额外选卡](../design-reviews/evidence/2026-10-27/combat/screens/11-extra-reward.png)。
- [界面布局回归](../design-reviews/evidence/2026-10-27/combat/ui-layout-regression.log)：保留36节点演练夹具，显式注入旧演练服务，不作为真实战斗验收；新实战另由上述测试覆盖。
- 所有最终检查使用独立测试目录；必需的启动检查和 Graphify 更新记录见同目录。Graphify候选覆盖不足时保留旧图，当前源码和状态文档为依据。

这些是规则、集成与渲染验证，不等同于人工游玩平衡验收。测试中的模拟驾驶通关时长不是玩家平均时长，也没有证明完整白门楼或旧版高密度场景达到性能目标。
