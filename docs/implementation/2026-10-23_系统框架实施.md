# 系统框架实施记录

基于 `9c1472e429af1168ec8e75f4c9adc980427a9235`，对话、任务、剧情物品、三关推进及恢复流程已接入实际游戏，保存、结算和共用界面一并升级。本轮直接完成，未使用 subagent，未提交、推送或公开发布。人物技能设计、技能数值和怪物机制不在本轮范围。

## 实际游戏流程

从主菜单“主线模式”选择三个故事槽之一，进入准备页查看任务与队伍；与NPC确认接取，出击并取得首通成果，返营交付后开放下一任务。第一章沿用“前哨清剿 → 裂隙推进 → 星核讨伐”，暂定目标为恢复通讯。台词可替换，修改稳定ID或内容版本时仍须遵守迁移规则。

`assets/story/chapter1.json` 是实际内容：3任务、6名交谈对象、3类剧情物品、13段对话、29节点、3条情报。前两类材料放在故事状态中，第三类沿用Boss核心；不占无尽携带位，交付NPC不必在出战队伍中。

准备页提供当前目标、接取/交付提示、共享队伍整备、继续对话、出击/续战/放弃/重访，以及任务、物品、情报、已见对话记录。新出击从本关初始构筑开始，继续恢复原阵容和局内成长。失败可查看结果并同关重试；练习回刷不推进主线，也不重复发永久材料。

## 架构改动

| 所有者 | 负责的规则 | 解决的问题 |
| --- | --- | --- |
| `story_content.gd`、内容JSON | 稳定ID、关卡映射、对话/物品/前置关系 | 台词与内容可替换，界面不硬编码任务顺序 |
| `story_state.gd` | schema2、内容版本1、状态约束、旧档迁移 | 新字段不被旧白名单丢弃，未来版本不被降级覆盖 |
| `story_progress.gd` | 接取、尝试、首通、交付、对话检查点、成果确认 | 准备、对话和结算共用一个业务写入口 |
| `dialogue_flow.gd`、`ui/story/` | 逐字显示、选择、跳过、关闭续读、只读记录 | 展示不代替玩家交付，回看不再次执行命令 |
| `save_file_store.gd`、`save_manager.gd` | 原子写入、有效备份、健康检查、身份校验 | 坏档不被当作空槽，恢复不串模式/槽位/战局 |
| `run_save_flow.gd`、`reward_flow.gd`、`game_session_flow.gd` | 冻结开局上下文、待提交结果、奖励恢复、结束与重试 | 中途退出或写入失败仍有恢复入口 |
| `run_outcome.gd` | 时间、关卡/波次、队伍、等级、装备和剩余点数摘要 | 死亡页、准备页和营地展示同一结果 |

继续复用共享弹窗、设置面板、队伍编辑器、奖励界面和战斗flow。暂停页删除重复设置控件，转为打开完整设置。没有新增全局事件总线、统一背包框架或第二套战斗成长系统。

### 保存与恢复

- 永久档区分缺失、可恢复、损坏及不兼容。备份保留上一次有效状态，恢复前另存坏档原文；列表和普通读取不删除文件。
- 新出击先保存 `starting` 意图，再建立同ID运行档，最后确认 `running`。阵容与关卡随尝试冻结，部分写入失败可以完成同一次出击。
- 胜利先写run中的待提交结果，再提交道具、任务、有限凭据和最近结果，最后清理匹配的run。永久档已提交而run尚在时，恢复只补清理；身份不匹配的文件不会被新出击暗中丢弃。
- 交付消耗、任务完成、情报、领取凭据和下一对话节点合并写入。重复提交、恢复展示、回看与回刷不重发材料。
- 小Boss奖励保存具体候选和上下文；续战先恢复装备奖励，再处理波末祝福。最终胜利提交失败保留待结算状态和重试操作。
- 骨头余额与当前 `run_id` 下的 `pickup_id` 凭据同时保存，成功后才移除拾取物；失败保留并限频重试。旧run快照不重复计入同一骨头，无ID的旧拾取物采用稳定快照序号ID；凭据随本局结束清理。
- 失败/放弃保存最近结果；保存失败不展示为已成功返营，窗口关闭也先检查战局写入结果。
- 旧故事进度0～3迁移为对应已完成交付，补情报和迁移凭据，不补材料、不扣旧核心；保留四人roster、三人队伍和旧运行快照。

### 界面、教学与反馈

- 对话先显示完整台词再推进；Tab选择、Enter/当前交互键确认、Esc保留检查点。跳过停在选择处，弹窗键盘焦点不穿透背景。
- 战斗HUD显示波数、波型与阶段，Boss波明确击败后结算；主线显示本关剩余目标时间。技能点高亮读取各角色自己的余额。
- 教学显示当前绑定，说明20波、独立技能点、整备急救和跳过；没有改变技能效果或敌人行为。
- 设置加入独立提示音音量、减动画、常亮出怪预警与剧情正文放大。界面/奖励/阶段/错误使用四类合成音；BGM与其他设置共用配置，避免覆盖。
- 性能记录补入模式、槽位、run/attempt身份及波次阶段，使样本能对应到实际战局。

## 尚未完成的验收与边界

- 自动三关通过既有胜利事件推进，不等于正常速度战斗通关。完整20波人工游玩、长时负载、短故事关成长节奏及失败体验仍需实玩。
- 剧情是可替换草案，第一章以后没有扩写；没有引入支线板、好感数值、走动故事营地或新经济系统。
- 提示音为开发合成音，完整战斗音效、占位资源授权/替换及跨平台发行未完成。
- run校验覆盖身份及外层容器，未为每种旧技能的嵌套负载补齐完整schema。骨头凭据不是历史收入总账，无法重建旧版本已经丢失的数据。
- 22项既有失败中也包括悬停时序和常驻阮石HUD的旧UI/测试合同差异；新框架通过不代表整个项目可发布。

下一轮优先正常速度实玩与文本打磨、按当前技能规则清理旧测试合同，再补发行模板和素材清单。扩展人物技能、怪物机制或第二章内容按后续任务决定。
