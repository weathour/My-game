# MIDI 节拍测试器

日期：2026-11-04  
状态：**用户实玩后暂缓，独立测试器与本记录作为历史原型保留。** 用户认为整个自动 MIDI 节奏战斗方案目前存在较大问题，暂不能推行；停止继续研究、调参、角色重配和游戏接入，只有用户明确提出时才重启。工具源码、用户按键记录和技术证据保留；程序检查通过不等于听感验收通过。[当前状态](../08_当前实现状态与后续重点.md)已回到白门楼既有玩法。

## 目的与范围

为[节奏战斗研究](../design-reviews/2026-11-04_节奏战斗与角色体系研究.md)提供可运行的独立 Python Qt 测试器，让听者比较音乐、不同自动参考时机与自己的自然跟拍。启动方式和使用说明见[测试器目录](../../tools/rhythm_tester/README.md)。本轮不改造游戏内战斗，也不把自动估计当作已经通过听者验收的主拍。

本机 Python 3.12 环境已装 PySide6 6.10.2、mido 1.3.3、NumPy 2.2.6；音频解码使用系统 FFmpeg。启动脚本优先使用依赖齐全的本地环境，否则通过 `uv` 准备。本机缺少的 `libxcb-cursor0` 使用官方 Ubuntu 包解压至工具本地 `.native`，启动时临时加入库路径，未修改系统库。

## 已实现

- 支持项目十二首 D2，以及使用者手动选择的配对 MIDI 与 OGG、WAV 或 MP3 音频。载入时分析 MIDI 和速度图，播放时比较参考时机。
- 提供自动主拍候选、MIDI 四分拍、鼓点起音和只听跟拍四种模式。自动主拍是候选，不是听觉真值；鼓点模式用于起音对照，也不等同主拍。只听模式隐藏参考拍点、提示声和评分，记录自然按键。
- 支持 J、K、空格跟拍，P 暂停或继续，R 重新开始，Enter 播放，忽略系统长按重复。可调整拍点层级、相位、窗口半宽上限、音画同步补偿、按键补偿、音乐音量和拍点提示声；层级、相位适用于自动候选及四分拍对照，提示声默认关闭。正按键补偿将判定用时间提前相应毫秒数，不改变音乐或原始按键时间。
- 实际窗口半宽还受相邻时机较短间隔的 45% 限制。同键可连续按或与其他键交替；一个参考时机跨 J/K/空格只计一次落窗，重复输入仍记录。这只是工具统计，不是已定的游戏出招互斥规则。
- 跳转、切换模式及重新开始产生新的记录段；有按键数据时切段及关闭会自动保存，也可手动导出 JSON 与 CSV 至工具的 `results/`。结果保留曲目哈希、模式参数、原始和补偿时间及与参考时机的偏差。落窗比例仅用于比较参考时机，不称节拍识别准确率；盲听段不评分。

源 MIDI 的 tempo map 用于积分时间；D2 裁切标记用于名义时间换算。外部素材缺少标记时，以零偏移处理，不保证对应音频的实际起点。时机估计和时间对齐未得到听感验收，当前不继续安排评估。

## 用户听感反馈与修正

用户反馈视觉上能够对齐，但跟随听到的节奏按键仍有偏差，节奏和位置似乎都不对。首版功能联测通过只说明既定测试场景的功能可运行，不能据此判断听感已经正确。

- 首版节拍灯在输入窗口前沿亮起，可比拍点提前约 90 ms；现改为拍点到达后短闪约 75 ms。自动主拍候选调整为各拍速共用 `1/32` 四分音符相位精度，并在共同的完整周期观测范围内比较，评分权重不变。第 10 首候选从每分钟约 216 次改为 108 次，第 02 首仍约 130 次；这只是候选变化，不证明哪种更合听感。十二首解析后的本机冷构建最长约 24.54 ms，测量不含 MIDI 解析，也不能代表其他设备性能。
- 新增独立的音画同步补偿，默认 0 ms，范围 -500 至 1000 ms。显示时间为 `processed - presentation_offset`，判定用按键时间为 `raw - presentation_offset - input_compensation`；原始按键时间保留。新 JSON 为 schema 2，JSON/CSV 增加音画补偿及对应时间，旧 JSON 保留不重写。改变窗口和两种补偿不会重建音乐；提示声关闭时切换参考模式也不重建音乐。
- Qt 音频环形缓冲请求值与本机运行时实测均为 50 ms；交互式跳转、停止、关闭和重置使用 reset，提示声重建与自然结束仍执行 drain。WHP01K 的 PipeWire 图报告约 150 ms 并非耳边实测，也不能简单与 Qt 缓冲相加。`--track 10 --presentation-offset-ms 150` 是当时拟使用的复听试值，默认仍为 02 和 0 ms，不自动猜设备延迟；现在不安排继续复听。
- 修复了低缓冲下把暂时 Idle 误当播放结束的问题。[修复前追踪](../../design/rhythm-combat-research-20261104/tester-feedback/false-eof-root-cause.json)显示播放约 0.69 秒、源缓冲仍有约 39.96 MB 未读时，旧代码就跳到约 208.8 秒的曲尾。现在需要源文件和已处理时间均到末尾才结束；可恢复的 Idle 不视为结束，若设备已停止且报告 underrun，则退回准备状态并报错。造成当次短暂停顿的底层原因未单独测定。
- [文件对齐检查](../../design/rhythm-combat-research-20261104/tester-feedback/audio-file-alignment.json)中，第 02 与 10 首按 30 秒分段的全声部汇总主峰均在 0 ms；部分单声部有周期别名。这不支持整曲裁切偏移的解释，也不能证明拍层正确或设备已校准。[旧记录分析](../../design/rhythm-combat-research-20261104/tester-feedback/analysis-diagnostic.json)的 660 次按键受画面和补偿影响，不是听者主拍真值；其中一段继承了 +100 ms 按键补偿，将同一记录反事实改为 0 后由 24/103 变为 88/103，不能据此认定某种参考方案更好。
