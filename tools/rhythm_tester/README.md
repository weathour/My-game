# MIDI 节拍测试器

**用户实玩后暂缓：此工具作为历史研究原型保留，不是当前任务。** 用户认为自动 MIDI 节奏战斗整套方案目前存在较大问题，暂不能推行；只有用户明确提出时才重启。工具源码、用户记录和验证资料保留。当前主线回到白门楼既有战斗、人物、剧情与音画，见[当前状态](../../docs/08_当前实现状态与后续重点.md)。

这个独立桌面工具曾用于听歌跟拍、比较 MIDI 参考时机并保存按键记录，不改变游戏战斗规则。自动主拍未通过听感验收；功能及历史验证范围见[实施记录](../../docs/implementation/2026-11-04_MIDI节拍测试器.md)。

## 启动

需要图形桌面、可用的音频输出，以及位于 `PATH` 的系统 FFmpeg 解码音乐。本机环境使用 Python 3.12；项目依赖声明允许 Python 3.12 或 3.13。在项目根目录运行：

```bash
./tools/rhythm_tester/run.sh
```

启动脚本优先使用 `tools/rhythm_tester/.venv` 中依赖齐全的现有环境，可离线启动；缺少该环境或依赖时，使用 `uv` 按 [pyproject.toml](pyproject.toml) 准备环境，首次准备可能需要联网。本机安装的版本为 PySide6 6.10.2、mido 1.3.3 和 NumPy 2.2.6。为补足本机缺少的 `libxcb-cursor0`，官方 Ubuntu 包解压在工具目录 `.native` 中，脚本启动时临时加入库路径；没有修改全局系统库。

也可以在其他目录调用 `run.sh` 的绝对路径。脚本保留调用时的工作目录，命令行 `--midi`、`--audio` 和 `--screenshot` 的相对路径按该目录解析。

## 使用

启动后默认准备第 02 首，不自动播放。选择项目的十二首 D2 曲目之一，或手动选择一对对应的 MIDI 和 OGG、WAV 或 MP3 音频。播放后听音乐，按 **J、K 或空格**跟拍；P 暂停或继续，R 重新开始，Enter 播放。系统长按产生的重复按键不计作新的跟拍。

当时曾预设曲目及音画同步补偿，例如 `./tools/rhythm_tester/run.sh --track 10 --presentation-offset-ms 150`，并保留按键补偿 0 ms；150 ms 只是设备报告下的试值，不是已测得的耳边延迟。正常启动使用第 02 首、音画同步补偿 0 ms，不会自动猜测设备延迟。此示例留作历史参考，当前不安排继续复听或调参。

- **自动主拍候选**：结合 MIDI 速度与各声部事件估计一组主拍，适合与听感比较。
- **MIDI 四分拍**：按 MIDI 速度图生成四分音符时机，供比较；四分音符不一定是人听到的主拍。
- **鼓点起音**：比较鼓声的起音与主拍；密集起音会合并，无鼓时使用其他音符起音作对照。
- **只听跟拍**：隐藏参考时机、拍点提示声和评分，只记录自然跟拍，避免参考画面引导判断。

自动候选和鼓点对照都不是人工验定的正确拍点，跟随它们的落窗比例也不是节拍识别准确率。可通过层级、相位、判定窗口上限及两种补偿比较不同设置；鼓点起音模式保留实际起音对照，不应用层级和相位。实际窗口半宽同时不超过相邻时机较短间隔的 45%。音乐音量可调，拍点提示声默认关闭。

**音画同步补偿**与**按键补偿**相互独立。音画同步补偿默认 0 ms，正值使画面和判定相对处理时钟延后；按键补偿为正时，用于判定的按键时间再提前相应毫秒数。两者均不改变音乐速度，原始按键时间会保留。蓝牙输出可能有延迟，系统报告的延迟不等于耳边实际延迟。

可连续按同一个键或交替按键；同一参考时机内，J、K 和空格共享一次落窗计数，额外按键仍记录为重复输入。这是测试统计方法，不是已定的游戏出招互斥规则。落窗比例以所有非盲听按键为分母，包含重复输入。

记录用于事后比较：每段保留曲目哈希和设置、原始时间、音画同步补偿后的时间、判定用时间及相对参考时机的偏差。跳转播放位置、切换模式或重新开始会另起记录段；已有按键记录的段在切换或关闭时自动保存，也可手动导出。默认输出到 `tools/rhythm_tester/results/`，每次会话写入一对 JSON 和 CSV。只听模式只记录按键，不评分或将其自动判为正确或错误；原有记录保留，不会被新格式改写。

## 配对与时间起点

MIDI 和音频需要是同一版本，并且时间起点需要对应。项目 D2 曲目的源 MIDI 与游戏音频在制作时存在裁切偏移；工具会读取 MIDI 中已有的制作标记进行名义换算。外部 MIDI 没有相应标记时按零偏移处理，这不保证它与音频同步，也不能代替设备延迟校准。先听实际音频，再比较结果。

## 验证状态

首版的单元、原生界面、真实音频联测及完整工程检查通过，但用户反馈跟随画面与跟随听感存在偏差；拍点显示、自动候选和同步补偿曾据此修正。低缓冲可能提前结束播放的程序缺陷也已修复，本轮单元、原生界面、真实音频联测及完整工程检查通过，见[实施记录](../../docs/implementation/2026-11-04_MIDI节拍测试器.md)。这些功能检查未证明跟拍听感已经可用，用户随后决定暂缓该方向。
