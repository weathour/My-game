# Changelog

## Unreleased

Entries within each section are newest first. Earlier experiments remain recorded for history and may be superseded by a newer entry above them; they are not all simultaneous current behavior.

### Fixed
- HUD switch widget in legacy layout never learned the actual team: `combat_skill_bar.update_team_role_statuses` returned early when `team_role_rows` was empty (legacy layout builds no team rows), so `set_switch_role_order` was never called and the switch portraits stayed on the hardcoded fallback trio swordsman/gunner/mage — with 机械师 on the team she never appeared in the switch widget and the top portrait fell back to index 1 until the layout was switched in the settings menu. Role-order extraction now runs before the rows check, so both layouts feed the real team order every frame.
- Level-up UI mechanic avatars: `TRAIT_HEAD_SCENES["level_trait_mechanic"]` and `LEVEL_TALENT_ROLE_SCENES["mechanic"]` in `scripts/level_up_ui.gd` pointed at the gunner's `gunhead.tscn` / `gunchange.tscn`, so mechanic trait cards and level-talent role entries showed the gunner portrait; they now use `mechanichead.tscn` / `mechanicchange.tscn`.

### Changed
- `Engine.get_frames_per_second()` is now queried once per rendered frame via a new frame-guarded `PERFORMANCE_GUARD.get_fps()` cache, replacing direct per-call queries in every hot-path FPS budget check (hit feedback / status visuals / bullet split & impact budgets, damage job queue, queued-hit threshold, spawn limits and budgets, mage/gunner ultimate visual pacing). Dense fights previously issued over a hundred engine FPS queries per frame.
- Minimap HUD no longer deep-copies its payload: `hud.update_minimap` ran `payload.duplicate(true)` on the full enemies/gems dictionary every 1/30s, but the payload is freshly built by `game_minimap_flow` each time and never retained elsewhere, so it is now assigned by reference.
- Performance recorder overhead removed from normal play: rolling frame samples now use a ring buffer instead of an O(n) `pop_front()` every frame once the 7200-sample window fills, and per-frame scope timing (`begin_scope`/`end_scope`, ~20 dictionary + clock calls per frame) is only active while someone actually reads it — the HUD performance overlay, the performance trace logger, or a benchmark session.
- Turret bombard updates hoisted to scene level: every enemy used to call `enemy_turret_bombard.update_bombards` from its own per-node physics tick (N calls per frame, N-1 of them no-ops after the built-in per-frame guard). It now runs once per physics frame from `game_physics_flow`, alongside the other scene-level batch updates.
- Batch simulation hot loops no longer pay per-node reflection every physics frame: `enemy_batch_simulation`, `enemy_projectile_batch_simulation` and `pickup_batch_simulation` now cache each script's batch-API support (`has_method` results are stable per script) in a static dictionary, and only write `batch_simulation_enabled` / toggle `set_physics_process` when a node actually transitions into batching instead of unconditionally every frame. At 150 enemies × 60Hz this removes tens of thousands of redundant dynamic dispatches and engine calls per second; eligibility itself is still evaluated per frame since it depends on runtime state.
- Enemy debug range overlay no longer runs in normal play: `game_scene_wiring` unconditionally created `EnemyDebugRangeOverlay` with combat ranges enabled, so every frame it iterated all runtime enemies and rebuilt 49-segment ellipse polylines for bosses even with debugging off. Combat-range drawing now defaults to off and is only enabled when developer mode is active at scene setup.
- Autosave spike halved: `save_manager.save_run` used to serialize the full run payload twice per autosave (once for `run_save.json`, once for `run_save_backup.json`); the backup is now a direct file copy of the freshly written main save (`save_file_store.copy_file`), so the ~2s autosave pays one `JSON.stringify` + one atomic write instead of two.
